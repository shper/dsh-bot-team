# 消息执行过程

升级后请先完全退出并重新启动 DSH，让 Host 加载新增接口。仅刷新页面或关闭再打开窗口，可能只更新前端：此时面板会提示“执行过程接口尚未加载”。完整重启后重新打开面板；旧消息缺少执行关联时会显示专门的历史记录提示。

在单聊或群聊中，右键一条 Bot 回复，选择 **执行过程**。右侧面板只显示这条回复对应的一次执行；等待中、执行中、完成、失败和已停止的 Bot 消息都可以打开。人类消息、系统消息和审批卡片没有这个入口。

面板按日志顺序显示触发输入、模型输出、工具调用与结果、`run_code` 内部调用、审批、模型重试和结束状态。展开参数或结果可以查看并复制完整记录；面板打开期间会接收实时更新，按 Esc 关闭并返回之前的焦点。窄屏时面板铺满聊天区域，界面跟随 DSH 的语言与主题。

**打开完整会话**会切换到占满 Bot Team 内容区的独立历史页面，展示这条消息保存的会话的全部轮次，包括输入、模型输出和工具调用。页面顶部的 **返回执行过程** 会恢复原回复的执行面板，保留 **打开完整会话** 按钮；聊天草稿和滚动位置也会保留。成员卡片的 **查看会话** 则打开该成员当前会话的完整页面，通过 **返回聊天** 回到原聊天；从侧栏查看其他单聊的历史也不会更换原聊天选择。加载中或读取失败时仍可返回。两者均为只读查看，不启动或恢复 Agent。成员后来更换工作目录、建立新会话，或被移出群，都不会把旧消息指向新会话。重试会为新回复保存新的一次执行关联。

升级前的消息没有可靠的逐轮关联，面板会明确提示；如果还能确认原成员，则提供单独标注的 **查看成员当前会话**。日志丢失或只保存了部分记录时也会显示相应提示。展示内容限于 DSH 记录的可观察执行过程，不包含系统提示、原始模型请求、内部推理流或不可见的模型状态。

## 关联与只读查询

每条新 Bot 回复在 `meta.execution` 中保存版本、job ID、实际 session ID、触发输入 ID、turn 和日志起止序号。Host 在提交输入前等待关联写入成功；通过精确的 inbox claim 或 `user/message.id` 确认所属轮次，不使用时间或文本相似度猜测。`submittedSeq` 是提交前日志长度，对应包含在内的搜索下界；`startSeq` / `endSeq` 是包含在内的事件索引，中断时允许末端为空。

读取接口：

```text
GET /api/bot-team.message-execution?groupId=…&messageId=…&afterSeq=-1&limit=100
GET /api/bot-team.session-history?groupId=…&sessionId=…&afterSeq=-1&limit=100
```

接口沿用 DSH 的认证路由，校验群与消息归属，只通过 `sessionQuery.observeSession` 读取快照，并释放 observation。不会启动或恢复 Agent。`limit` 默认 100、最大 300；`nextSeq` 按实际检查过的原始事件推进，过滤掉不可展示的事件后也能继续分页。冷日志的分页限制的是响应体，SDK 仍可能读取整个会话日志。

完整会话接口必须确认会话属于该群的当前成员，或有该群 Bot 历史消息的有效执行关联，才会读取日志；客户端提供的会话 ID 不能直接授权访问。读取完成后会再次核对归属。Bot Team 自管会话可能没有 DSH 原生子会话所需的父地址，因此历史查看直接使用只读查询，不调用原生普通会话导航，也不修改既有日志身份。

SSE `execution.updated` 通知消息 ID、会话 ID 和日志序号，关联变更时附带元数据。客户端只在面板打开时拉取，完整会话会接收同一会话不同轮次的更新；关闭或切换目标会中止旧请求。这些通知不会覆盖正在流式输出的聊天文本。

```sh
cd bot-team
npm run check

```
