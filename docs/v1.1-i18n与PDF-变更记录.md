# v1.1 中英双语与导出 PDF — 变更记录

> 版本：`dsh-bot-team@1.1.0`（在 1.0.0 公开发行版之后；docs 的 v0.5–v0.8.1 是发布前 0.x 迭代）。
> 范围：M5 待办中的「完整 i18n（zh/en）」与「导出 PDF」两项。测试：`npm test` 134 条（133 通过 + 1 条按系统 CJK 字体条件跳过）。

## 1. 中英双语（i18n）

### 1.1 接入 DSH 语言服务

- Client 插件新增 `locale` 注入；`apply(ctx)` 用 `ctx.effect(() => ctx.locale.register('botTeam', { zh, en }))` 注册字典，`ctx.locale.bind('botTeam')` 取翻译函数。
- `main` 页面注册带 `locale: 'botTeam'`；页面再用 `useLocaleRevision()` 订阅 `ctx.locale`，语言切换时立即重渲染，不需要刷新页面。
- 语言由 DSH **设置 → General → Language** 统一切换；插件不另存语言偏好。

### 1.2 字典与渲染时翻译

- UI 字典以中文原文为 key，`UI_EN` 是英文映射，`UI_ZH` 由同一批 key 生成恒等字典（490 条；含静态文案与带 `{count}`/`{name}` 占位符的动态模板）。
- 单文件 Client 用一个 `h()` 包装 `React.createElement`：所有字符串子节点与 `title` / `placeholder` / `aria-label` 等属性在渲染时查表；因此常量表（任务状态、优先级、审批状态、聊天显示模式等）也能跟随语言切换，而不是在模块加载时冻结。
- 动态文案改为 `uiT('...{name}...', { name })`，占位符由 DSH locale 的 `translate` 替换；日期分隔与列表时间在英文下使用 `Today / Yesterday / Sep 5` 等格式。
- 导出 Markdown / HTML / PDF 的标签（成员、消息数、导出时间、轮次、附件等）使用同一套翻译。

### 1.3 内容保护（不翻译用户数据）

- 消息正文走 Markdown 渲染器，包在 `withRaw()` 中；作者名、群名、Bot 名、任务标题、附件名、技能名、人格正文等通过 `raw: true` 或 `withContent()` 保护。
- `withContent` 在组件子树内建立精确值集合：即使某个群恰好叫「设置」，也不会把设置按钮的文案当成内容；反过来，名为「设置」的群标题保持原文。
- 宿主生成的 **系统事件消息**（讨论结束/停止、评审请求、返工请求、任务验收解锁、审批请求）在渲染时按事件模式翻译（`translateSystemText`），历史消息也生效；未知事件保持原文。

### 1.4 验证

- `test/i18n.test.js`：
  - 字典 key/value 非空、占位符集合与 key 一致；
  - 英文下 UI 变为英文而消息/姓名/群标题保持原文；
  - 系统消息、审批卡片翻译；
  - 群列表「设置」按钮为 Settings，而群名「设置」保持原文；
  - `apply()` 确实向 DSH locale 注册 zh/en，并可按 active 语言切换。
- 语言切换通过 DSH 的 locale revision 通知页面重渲染；没有引入轮询或刷新。

## 2. 导出 PDF

### 2.1 Host 端生成（无浏览器打印）

- 新增 `host/pdf.js`：直接写 PDF 1.7，**不依赖浏览器打印对话框、不需要 PDF 服务**。
- 新增 `GET /api/bot-team.export.pdf?groupId=&lang=`，登录态栅栏内返回 `application/pdf`；`Content-Disposition` 同时带 ASCII 回退与 `filename*=UTF-8''`，文件名含群名与日期。
- Client 在群头部「···」与输入框 **+ → 指令** 增加「导出 PDF」；`fetch` 取回 Blob 后下载。单聊不提供 PDF（与 HTML 一致）。
- 失败返回可读错误：无字体 → 501 + `pdf-font-unavailable`；其他生成错误 → 500。

### 2.2 字体发现与子集化

- 字体按平台自动发现：
  - macOS：`Hiragino Sans GB.ttc`、`Arial Unicode.ttf`、`STHeiti Light.ttc` 等（发现时会检查 `OS/2 fsType`，无嵌入/禁止子集的字体自动跳过，例如宋体）；
  - Windows：`msyh.ttc/.ttf`、`simsun.ttc`、`simhei.ttf`、`arialuni.ttf`；
  - Linux：文泉驿、AR PL、Droid Sans Fallback 等 TrueType 常见路径。
- 可用 `config.pdfFontPath` 指定 TrueType/TTC 文件（覆盖自动发现）。
- 用 `fontkit` 做 cmap 查询、布局度量和 **字形子集**；只嵌入实际用到的字形，5 条消息的示例 PDF 约 80 KB，80 条消息/11 页约 200 KB 级。
- 嵌入为 Type0 / CIDFontType2 / Identity-H，带 `FontFile2`、`W` 宽度数组与 **ToUnicode CMap**，正文可选中、可搜索、可复制。
- 动态 `import('fontkit')`：缺依赖时插件仍能加载，只在导出时返回可读错误。`package.json` 声明 `dependencies.fontkit ^2.0.4`。

### 2.3 排版

- A4（595.28 × 841.89 pt），页边距、自动换行（CJK 按字、拉丁按词）、页眉群名、页脚「第 X / Y 页」。
- 支持标题、段落、粗体（填充+描边模拟）、行内代码、删除线、引用、无序/有序列表、代码块（灰底）、表格、分隔线；消息头含 `#seq`、作者、轮次/总结/评审通过/需修改/已停止等徽标；附件显示名称与大小；审批卡片按系统消息处理。
- 宿主系统消息在英文 PDF 中按事件模式翻译；群名、Bot 名、消息正文等保持原文。
- 明确限制：无图片/头像、链接不可点击、emoji 可能缺字；需要完整视觉效果时用 HTML 导出。

## 4. 已知限制

- 语言只覆盖界面与宿主事件消息；Bot 回复、群名/Bot 名、人格模板正文、部分宿主错误保持原语言。这与「内容不翻译」的边界一致。
- PDF 依赖系统 CJK TrueType 字体；容器/精简系统无字体时导出失败，需要 `pdfFontPath`。Linux 的 Noto CJK OTF（CFF）不在自动发现范围内。
- PDF 无图片/头像、链接不可点击、emoji 可能显示为缺字；正文文本可选中。
- 新增 `fontkit` 运行时依赖；本地 link 安装需要先在 `bot-team/` 执行 `npm install`，npm/Git 安装会由包管理器拉取。
