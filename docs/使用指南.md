# Bot Team 使用指南

> 适用源码版本：`dsh-bot-team` 1.3.0，DSH Desktop 0.2.1-rc.x。包含后台会话、`/new`、讨论与辩论、版本检测和数据存储设置；讨论/辩论的具体流程见[专页](<讨论与辩论.md>)。npm 发布状态见[发布指南](<发布指南.md>)中的说明。
> 加载本地修改时，先在插件管理 **disable → enable** 重新加载 Host，再刷新现有页面（⌘R）；只刷新浏览器不能加载新的 Host 模块。左侧栏点 **Bot Team** 图标进入工作台。

---

## 1. 核心概念

| 概念 | 说明 |
|---|---|
| **单聊** | 你与一个 Bot 的一对一会话；每个 Bot 创建后自动拥有，无需 @，有自己的消息时间线与会话记忆 |
| **群 / 话题** | 一个多 Agent 聊天室，有独立消息时间线、成员、工作目录与 token 用量 |
| **分组** | 左侧「群聊」里的自定义文件夹（一层），可折叠、可拖动排序；群只能属于一个分组，删除分组不会删除群 |
| **Bot** | 全局可复用的 Agent 定义：显示名、头像、模型、BOT.md。同一个 Bot 可加入多个群，每个群内是**独立会话与记忆** |
| **成员** | Bot 在某个群里的实例；有独立会话记忆和持久日志。后台会话不进入 DSH 主会话列表，继续对话、提问和审批均在 Bot Team 内完成 |
| **工具权限** | 所有 Bot 统一为全能力 Bot，不提供只读版或按角色裁剪工具的版本；具备文件读写、搜索、联网、命令执行、Skill，session 沙箱为 `workspace-write`，可访问范围由群/单聊工作目录限制 |
| **@ 提及** | 只有被 @ 的 Bot 会回复；一条消息可 @ 多个 Bot（并行回复） |
| **附件 / Skill** | 输入框左下角 **+** 打开 DSH 风格分组命令菜单（文件 / 文件夹 / 技能 / 提及 / 停止 / 导出 / 设置）；键入 `/` 也可选 Skill。文件存入 DSH 附件库，Bot 用只读路径读取；Skill 以 `/skill-name` 形式随消息发送，由 DSH 在当轮加载 |
| **语言** | 跟随 DSH **设置 → General → Language**；界面与宿主事件消息在 zh / en 间即时切换，Bot 消息、群名/Bot 名等用户内容保持原文 |
| **评审** | 对任意消息「请人评审」，评审者输出 `结论：通过/需修改`；可「让作者修改」 |
| **讨论** | 结构化讨论至少 2 人，按观点/质询/收敛推进，有轮间小结和可选最终总结；轮数可自定义，结构化讨论 2–20 轮，经典讨论 1–20 轮，旧工具默认 2 轮 |
| **辩论** | 正反方各 1 人，可另选独立裁判；开篇、交叉问答、总结陈词和可选裁决，无裁判不生成胜负 |
| **任务** | 指派给某个 Bot 的工作项：pending → 派发 → 交付 → 评审/验收 → 需修改返工；有验收标准、交付物、**优先级**与**依赖** |

## 2. 快速上手

没有 Bot 且没有群聊时，显示「开始使用」欢迎页及侧栏 **开始使用** 入口：主入口是 **创建 Bot**，也可选择次入口 **创建群聊**。创建成功后进入新 Bot 单聊或新群，取消时留在欢迎页。存在任一 Bot 或群聊时，欢迎页及该侧栏入口均隐藏，不能返回欢迎页；删除全部 Bot 和群聊后恢复。欢迎页隐藏右侧 Bot 库，右上角 **快速上手** 可打开三步引导。

> 左下角 **「Bot 管理」按钮** 是（全局）Bot 管理入口：查看全部 Bot、所属群，新建/编辑/删除全局 Bot。
> 界面已统一 UI 风格（v0.6.2）：弹窗分组表单、等宽栅格、粘性头尾；Bot 默认使用程序化机器人头像，可随机换配色/表情、选一套本地 SVG 插画，或上传自定义图片；自己的消息优先显示 DSH 登录账号头像；页面跟随 DSH 的浅色/深色主题；越界操作会在群时间线生成审批卡片。

1. 在欢迎页点击 **创建 Bot**，或点「单聊」右侧 **+**，填写创建弹窗并保存，成功后会**自动打开它的单聊**；也可以点击 **创建群聊** 或「群聊」右侧 **+** 建群（可填话题、工作目录），保存成功后直接进入新群。
2. 群聊里右侧「+ 添加」拉入已有 Bot；没有 Bot 时点「+ 新建 Bot」创建。新建/编辑群时可设置群头像（随机配色 / SVG 插画 / 上传图片）。
   - 显示名（就是 @ 用的名字，需唯一）
   - 头像（默认按名称生成机器人头像；可随机换配色/表情、选插画或上传图片）
   - Provider / Model / Reasoning effort
   - 工具默认全开（文件读写 / 搜索 / 联网 / 命令 / Skill），无需再选角色
   - BOT.md（人格 + 工作规范，一个文件；旧版 SOUL.md/AGENT.md 会自动合并读取）——保存后下一轮回复生效。
3. 群聊输入框输入 `@` 选择成员后发送；回复实时流式出现。单聊里直接发消息即可，不需要 @。输入框左下角 **+** 可打开分组命令菜单（文件 / 文件夹 / 技能 / 提及 / 停止 / 导出 / 设置）；也可以在输入框直接键入 `/` 选择 Skill。
4. 更多操作：
   - 悬停消息 → 气泡侧边图标：**回复 / 复制 / 评审 / 修改 / 重试**；在消息上**点右键**也会弹出完整菜单（含「复制为引用」「定位原消息」），回复会带引用条，点击气泡里的引用块可跳回原消息
   - 群头部「讨论/辩论」→ 选择多成员讨论或 1v1 辩论 → 填议题、参与者与轮数；状态卡显示阶段和当前发言者，可暂停、继续、重试、补充材料、提前结束或停止，详见[讨论与辩论](<讨论与辩论.md>)
   - 群头部「···」→ 添加成员 / 编辑群 / 导出 Markdown / 导出 HTML / 导出 PDF / 删除群
   - Bot 回复右键 **执行过程** → 查看这条回复的输入、模型输出、工具及内部调用、审批、重试和结果；执行中实时更新，支持展开与复制完整记录，详见[消息执行过程](消息执行过程.md)
   - **继续对话 / 提问 / 审批** → 直接在 Bot Team 中完成，待处理问题和审批显示在聊天区域；后台 Bot 不新增 DSH 主会话列表条目
   - **查看日志 / 完整日志** → 打开独立只读页面，默认显示结构化执行，可切换「原始事件」逐条查看完整 JSON，按类型 / 文本筛选并复制，保留 reasoning、attempt、compaction、未知事件及完整 payload；「导出原始日志」下载 JSONL。通过「返回聊天」回到原聊天，从执行面板打开时可通过「返回执行过程」恢复原面板
   - **原生目标（goals）续跑**：每轮自动续跑分别记录回复与执行日志，可从对应回复打开「执行过程」；「完整日志」仍可查看整个会话
   - **任务管理（模型工具/API）**：右侧任务面板及「新建任务」入口已移除；需要明确跟踪工作项时，在普通会话中使用 `bot_team_task_create/list/update` 创建、查询、派发、中断、评审和验收任务。已有任务数据与群消息中的任务状态标记保留
   - **依赖**：依赖的任务全部「已验收」后才能派发，未就绪时模型工具返回阻塞信息；前置任务验收后自动解除阻塞并写系统消息
   - 错误回复上「重试」；输入框底部「停止」中断当前群所有回复

### 在当前聊天开始新会话 `/new`

可完整输入 `/new` 后发送，也可点输入框 **+ → 指令 → 新建会话**，或顶部 **··· → 新建会话**。`/new` 后不能跟参数或另一段正文；正文中提到这个词、代码块或引用中的 `/new` 都不会替你新建。斜杠菜单中先选中命令会补全 `/new`，再发送执行；输入法选词不会触发切换。

单聊只重开当前 Bot 的这段对话；群聊为**本群全部成员**同时切换，包括当前停用的成员。聊天名称、成员、人格与模型、群主题、项目目录及文件不变，其他聊天不受影响。新段不自动携带旧聊天、执行历史、摘要、目标或任务；Bot 仍能按你的新要求读取项目文件。新建本身不调用模型、不消耗 Token，也不重置每日预算。各 Bot 首次需要执行或准备 Skill 时才建立本段底层 session，所以刚新建时显示「本会话尚无日志」是正常的。

**草稿和多个窗口。** 从菜单新建成功会保留正文、手动 @、附件和上传状态，清除旧回复目标及仅因回复自动插入的 @；命令成功只消费该次 `/new` 文本，失败保留输入。其他窗口开始新段时，当前非空草稿保持原归属，出现「聊天已开始新会话，草稿已保留」。确认要在新段继续时，点击 **将草稿用于当前会话**，再主动发送；系统不会自动重发冲突请求。

**忙时为什么不能新建。** 回复运行或排队、未结束的讨论/辩论（包括已暂停）、成员/项目设置、Skill 准备、提问或审批、目标自动续跑、后台作业、子代理和未执行 inbox 都可能阻塞切换；宿主缺少查询能力或状态无法确认时也会拒绝，并给出原因。可先处理提示中的工作或等待其完成。点「停止回复」只说明已发出停止操作，后台工作及保存收尾仍须重新检查，不保证马上可 `/new`。已经接纳的输入若只剩写盘，会先等它保存完成，再提交新会话。当前公开 SDK 无法可靠确认 external 子代理是否结束，因此即使其目录显示 inactive，冷重启后已有 external/unknown 记录仍可能提示 unknown busy；不能靠停止或重启保证解除。

**历史仍在原时间线。** 新旧段之间有分隔，连续空段也会保留；上翻仍可查看、复制和导出旧消息。分隔处的日志入口与顶部 **本会话日志 / 本会话尚无日志 / 上一会话日志** 指向各自实际使用的 session，查看不会恢复旧执行。已打开的旧日志不会因新建自动跳到新段。

**明确带入旧内容。** 回复或引用选中的历史消息，会把该条消息的快照带入当前请求，不会连带补入上一段的其他消息。旧任务、讨论、评审/修改和重试链保留为历史；需要继续时在当前段重新提出请求或创建任务，旧依赖不会自动解锁并派发到新段。

会话数据模型、提交失败恢复与 HTTP 契约见[新建会话](<新建会话.md>)。

### 引入文件夹 / 项目

1. 在单聊或群聊的输入框点 **+ → 文件夹**。
2. 点击 **选择文件夹…**，或填写运行 DSH 的电脑上的项目绝对路径（支持 `~/`），然后点 **引入项目**。目录必须存在，不能选择普通文件。
3. 输入框会显示 **当前项目** 和完整路径。直接给 Bot 发任务，例如「查找这个项目的登录逻辑，修复失败后无法重试的问题」；群聊仍需 `@` 要执行的 Bot。Bot 的检索、读写和命令在该项目目录执行。
4. 后续消息持续使用该项目，刷新和重启后保持。每个聊天同时引入一个项目；点 **更换** 切换，点 **×** 恢复该聊天的默认工作目录，项目文件保留。

项目是原目录引用，不会打包上传整个文件夹。任务运行、排队或存在未结束的讨论/辩论时不能切换目录；`paused` 也会阻塞，`stopping` 仍需等待原生执行收尾并重新检查。请先完成或停止相应流程。切换目录后，下一次执行会为 Bot 创建与新目录对应的会话和文件沙箱，聊天记录和旧会话文件保留；项目中可用的 Skill 列表也会重新读取。

### 单聊与分组（v0.7）

- **单聊置顶**：左侧「对话」栏固定「单聊」在上、「群聊」在下。每个 Bot 都有一行单聊（头像 + 名称 + 最后消息 + 时间），Bot 回复中显示绿点。
- **自动创建**：新建 Bot 后，Host 立即创建它的一对一会话并自动切过去；旧 Bot 在升级后也会由 schema v6 迁移补齐。单聊不能删除，删除 Bot 时会连同单聊与消息一起删除。
- **不需要 @**：单聊输入框没有「@ 提及」按钮，每条消息都直接发给该 Bot；单聊复用群聊的流式回复、停止、引用/复制/右键菜单、导出 Markdown 与 token 用量。评审、讨论、任务管理是群聊专属流程，单聊里不提供（Host 也会拒绝）。
- **右侧面板**：单聊右侧显示 Bot 头像、provider/model、累计 token 用量，以及「编辑 Bot」「查看日志」。「查看日志」进入独立只读记录；人格仍在「编辑 Bot → BOT.md」维护。
- **新建分组**：「群聊」标题右侧的文件夹图标（或群操作菜单里的「＋ 新建分组…」）；输入名称即可。分组名不可重复。
- **把群放进分组**：编辑群弹窗的「分组」下拉，或右键群 / 行尾「···」→「移动到分组」；也可以直接把群拖到分组标题上。
- **自定义排序**：拖动群可在分组内或跨分组排序；拖动分组标题可调整分组顺序；菜单里也有「上移 / 下移」。排序保存在 Host，刷新与其他页面一致。
- **展开/收起**：「单聊」「群聊」「未分组」和每个自定义分组左侧都有箭头，点击折叠/展开；状态存在浏览器 `localStorage`（`bot-team.sidebar.sections`），刷新保持。图标栏模式下不显示分组标题，按「单聊 → 群聊」顺序显示头像与分隔线。
- **删除分组**：分组内的群会回到「未分组」，不会被删除。
- **右侧面板收起**：聊天右上角的「面板」图标按钮，以及右侧面板标题栏的「»」，都能收起/展开成员 / 讨论 / 单聊信息面板；收起后消息区变宽，按钮仍留在聊天头部用于重新展开。偏好存 `localStorage`（`bot-team.right-panel.collapsed`），刷新保持；窗口宽度 ≤1100px 时右侧面板本身会自动隐藏，切换按钮也隐藏。「开始使用」欢迎页不显示右侧 Bot 库。
- **旧 Host 提示**：如果只刷新页面、但没有重启 DSH / 重新启用插件，侧栏的单聊区会显示「Host 仍是旧版本」提示；这是 Host 模块尚未加载新代码，重新启用插件或重启后再刷新。bundle patch 或 preset 声明变更时应重装 bundle 或完整重启。

### 左侧群栏收起（v0.6.5）

- 群栏头部 `群聊` 右侧的方形图标按钮用于收起侧栏（232px → 68px），再点「展开侧栏」恢复。
- 收起后只显示群头像：选中态淡蓝底、Bot 回复中的绿点仍在；鼠标悬停头像可看群名与最后一条消息。
- 头部只保留「展开侧栏」「+ 新建」两个图标，底部「Bot 管理」「设置」变为上下排列的图标，悬停提示含义不变。
- 偏好存在浏览器 `localStorage`（`bot-team.sidebar.collapsed`），刷新页面、切走再回来都会保持；存储不可用时仅当前会话生效。
- 键盘 `Tab` 到群头像后按 `Enter` / `Space` 可切换群；群栏宽度过渡在 `prefers-reduced-motion` 下关闭。

### 群聊信息流（v0.6）

- **分组与时间**：同一 Bot/人 5 分钟内的连续消息合并为一组，只在组首显示头像和名字；跨天或间隔 ≥5 分钟显示「今天 / 昨天 / 日期 + 时间」。
- **自己 / 他人**：自己在右侧蓝底气泡，其他成员在左侧白底气泡；头像在气泡外侧。
- **操作**：悬停任一消息，气泡侧边出现图标工具栏；在消息上点右键弹出同样的操作菜单（外加「复制为引用」「定位原消息」）。`回复` 会在输入框生成引用条，发送时写入原消息 `replyTo`；群聊里回复 Bot 消息会自动在输入框带上该 Bot 的 `@`（切换回复对象时同步替换，单聊与回复人类消息不插入），避免回复因缺少 `@` 不触发。
- **右键菜单**：位置跟随光标并自动收进视口；方向键切换、Esc / 点空白 / 滚轮或触摸滑动关闭；选中文字后右键或右键链接时保留浏览器原生菜单。
- **删除消息**：单聊和群聊的普通消息上点右键 → **删除消息** → 确认，可删除自己发送的消息或 Bot 回复。删除成功后消息立即移除，刷新后仍保持，其他已打开该聊天的页面也会同步；删除失败则保留消息并提示错误。生成中的回复需先停止，仍有后台执行占用该消息时会提示稍后重试。删除只移除聊天时间线中的该条记录，Bot 已有会话记忆、完整日志和附件保留。
- **滚动**：上翻阅读时新消息不会把你拉回底部，而是显示「N 条新消息 / 回到底部」；加载更早消息会保持当前阅读位置。
- **引用定位**：点击消息气泡里的引用块可滚动到原消息并高亮；原消息不在当前已加载范围时提示先加载更早消息。
- **输入**：输入框自动增高；`@` 选择器支持 ↑/↓ 选择、Enter 确认、Esc 关闭；底部显示正在回复的 Bot 数量与停止按钮。
- **+ 命令菜单**：左下角 **+** 打开与 DSH 一致的弹层，分「添加」和「指令」两组；行内是图标 + 中文名 + 英文别名 + 右侧说明，支持 ↑/↓、Tab、Enter、Esc。
  - **添加**：**文件** 多选本地文件（单文件 ≤32 MB、每条 ≤10 个）→ 上传后显示草稿附件条；**技能** 或键入 `/` 打开 Skill 选择器；群聊可 **提及成员**。
  - **指令**：**新建会话**（`/new`，作用于当前单聊或全群）、**停止回复**（有回复时）、**导出 Markdown**、**导出 HTML** / **导出 PDF**（群聊）和 **消息设置**。
  - Skill 选择器支持 ↑/↓、Tab、Enter 选中，Esc 关闭；选择后写入 `/skill-name` 并附带尾部空格。Skill 列表只显示 `userInvocable` 的条目，`modelInvocable: false` 标为「仅手动」。
- **附件消息**：发送后气泡显示文件名、大小与「只读附件」；Bot prompt 里带只读路径，可用文件工具读取。图片/二进制按通用文件保存，不会作为图片输入直接送给模型。附件不随消息删除；文件存在 `$DSH_HOME/attachments/v1`。
- **头部**：群名、成员/话题摘要、「N 个回复中」状态；「讨论」为常用按钮，其余群操作在「···」菜单。
- **模型信息**：Bot 回复底部的模型名与 token 用量默认隐藏；悬停消息时显示，模型名提示里包含 provider / reasoning effort。

### 语言与导出 PDF（v1.1）

- **语言**：界面语言由 DSH 统一管理。打开 **设置 → General → Language** 切换 **简体中文 / English**，Bot Team 页面、菜单、弹窗、空态和提示即时更新，无需刷新。宿主生成的讨论 / 评审 / 审批事件消息也会按当前语言显示；Bot 的回复、群名、Bot 名、人格模板正文等属于内容，不会被翻译。
- **导出 PDF**：群头部「···」→ **导出 PDF**，或输入框 **+ → 指令 → 导出 PDF**。Host 直接生成 PDF 文件下载，不需要浏览器打印对话框：A4、页眉群名、页脚页码，正文文本可选中与搜索。
- PDF 使用系统中的 CJK 字体（macOS 优先 Hiragino Sans GB / Arial Unicode（宋体等无嵌入许可的字体自动跳过）；Windows 微软雅黑/宋体；Linux 文泉驿等），只嵌入实际用到的字形，文件较小。**没有可用 CJK 字体**时会提示并在 HTTP 层返回 501；可在 `config.pdfFontPath` 指定一个 TrueType/TTC 字体路径。
- PDF 是轻量排版：无图片/头像，链接不可点击，emoji 可能缺字；需要完整视觉效果时可同时导出 HTML。

### 设置、版本更新与数据存储

- 左侧栏底部 **设置** 打开 Bot Team 设置；弹窗是左侧模块导航 + 右侧内容，模块为 **消息设置**、**侧边栏设置**、**数据存储**、**关于**。
- **消息设置**：原有「模型名称 / 输入 Token / 输出 Token / 平均回复速度」的悬停/常驻/隐藏设置整体移到这里；效果预览、恢复默认、取消、保存设置的行为不变。
- **侧边栏设置**：**显示单聊**默认开启；关闭并保存后，侧栏的单聊列表和收起状态下的单聊图标都会隐藏。偏好保存在当前浏览器，刷新或重新进入后仍有效；取消放弃修改，恢复默认会重新开启。
- **关于**：显示插件说明、当前版本、包名和开发者；版本 / 包名 / 开发者来自 [包清单](<../package.json>)，由 Host bootstrap 的 `plugin` 字段下发。**版本检测** 会异步读取 npm；检测期间按钮禁用，页面仍可操作，失败可重试并保留上次成功信息。
- 插件启动后也会异步检测。版本按 SemVer 比较，使用运行中 DSH 的真实版本校验兼容要求，仅推荐不高于 npm `latest` 的稳定兼容版本；如果最新版不兼容，会说明要求，并显示仍可安装的较低兼容版本。无法确认 DSH 版本时不推荐升级。
- 发现兼容更新后，展开或收起的 **设置** 入口都会显示小圆点，点击直接打开「关于」。页内展示 npm 最新版本、可更新版本、当前 DSH 与上次成功检测时间；尝试读取仓库变更日志中对应已发布版本的更新说明，读取不到时仍可点击 **查看更新说明**。
- **前往更新** 打开 DSH 原生插件管理页。当前第三方插件需卸载后按「关于」页提供的精确包名（例如 `dsh-bot-team@1.3.0`）重新安装，再重启 DSH；按钮不会自行安装或卸载。
- **数据存储**：显示数据存储目录、真实 DSH session 说明、BOT.md 位置、单聊与群聊默认工作目录；自定义目录以实际配置为准。
- 左侧导航支持 ↑/↓/Home/End 切换，选中项有高亮与焦点环；「关于」和「数据存储」页的底部按钮是「关闭」，不显示保存。

## 3. 模型工具（普通会话里可用）

当前工作区提供 10 个模型工具。在任意 coding session 里对主 Agent 说"建一个群让 A/B 讨论 X"，主 Agent 会按需调用：

| 工具 | 用途 | 关键参数 |
|---|---|---|
| `bot_team_list` | 列群/成员/最近消息 | `groupId?`、`includeMessages?` |
| `bot_team_create_group` | 建群 + 拉 Bot（缺的自动建） | `title`、`topic?`、`workspaceCwd?`、`bots[{name, provider?, model?}]` |
| `bot_team_send` | 发消息并返回回复 | `groupId`、`text`、`mentions[]`、`wait` |
| `bot_team_review` | 请某 Bot 评审并返回 verdict | `groupId`、`reviewer`、`messageSeq?`、`instructions?` |
| `bot_team_discuss` | 经典/结构化讨论，返回状态、transcript/summary | `groupId`、`topic`、`members[]?`、`format?`、`rounds?`、`summarize?`、`summaryMember?`、`perspectives?` |
| `bot_team_debate` | 1v1 辩论，有裁判时返回 verdict | `groupId`、`topic`、`pro`、`con`、`judge?`、`proPosition?`、`conPosition?`、`rounds?` |
| `bot_team_discussion_control` | 查看、暂停、继续、重试、收束、停止或补充材料 | `discussionId`、`operation`、`text?`、`contextMessageIds?`、`expectedRevision?`、`requestId?`、`wait?` |
| `bot_team_task_create` | 建任务（可一步派发） | `groupId`、`title`、`assignee`、`reviewer?`、`priority?`、`dependsOn?[]`、`dispatch?`、`wait?` |
| `bot_team_task_list` | 任务列表（优先级排序） | `groupId`、`taskId?`、`status?`、`includeClosed?`、`limit?` |
| `bot_team_task_update` | 任务流转/编辑/一键派发 | `taskId`（dispatch_ready 时可省略）、`action`（dispatch/dispatch_ready/review/accept/request_changes/revise/cancel/update）、`groupId?`（dispatch_ready）、`wait?`、`force?` |

讨论/辩论还支持 `goal`、`background`、`responseLength`（short/standard/detailed）、`language`（auto/zh/en）、同群显式引用 `contextMessageIds`、`wait` 与 `timeoutMs`。工具使用成员名字，未知或同名歧义会报错，空 `members: []` 不代表全员。`wait:true` 在暂停时也会返回；只有 `done/stopped` 才是终态，超时或 `wait:false` 不表示已完成。字段与示例见[讨论与辩论](<讨论与辩论.md#模型工具>)。

> Bot 成员禁用发起与控制类工具，避免递归编排；只读列表仍可使用。`enableModelTools: false` 可整体关闭。单聊是 UI 侧的一对一会话，不会出现在 `bot_team_list` 里；模型工具面向群聊。

## 4. 配置（`cordis.patch.yml` 的 `config`）

| 字段 | 默认 | 说明 |
|---|---|---|
| `dataDir` | `$DSH_HOME/dsh-bot-team` | 插件数据根目录（人格 + 工作目录） |
| `botsDir` | `<dataDir>/bots` | BOT.md（兼容旧 SOUL.md/AGENT.md）目录 |
| `defaultCwd` | Host 进程 cwd | 旧记录兜底；新群 / 单聊使用各自目录 |
| `migrateLegacyLayout` | true | 首次启动迁移旧的 `$DSH_HOME/bot-team` 布局 |
| `maxParallelTurns` | 3 | 群级并行回复上限 |
| `maxContextMessages` | 40 | 单轮注入历史消息上限 |
| `turnTimeoutMs` | 0 | 单轮执行时长上限（毫秒）；`0` 不限制时长，显式配置正数时按该值超时，已有正数配置继续有效 |
| `dailyTokenBudget` | 5000000 | 每群每日 token 上限 |
| `botSandbox` | true | 是否把 Bot session 显式设为 `workspace-write` 沙箱 |
| `botApprovalPolicy` | ask | `ask`：越界/升权时在 Bot Team 中生成审批卡片并授权；`never`：直接拒绝所有需审批操作 |
| `autoDispatchReady` | false | 依赖解锁后是否自动派发变为就绪的任务 |
| `enableModelTools` | true | 是否暴露 `bot_team_*` 工具 |
| `toolWaitTimeoutMs` | 180000 | 模型工具等待超时 |
| `smokeTest` | false | 仅验证用：激活时跑端到端冒烟/恢复检查 |
| `pdfFontPath` | 空 | 可选：PDF 导出的 CJK TrueType/TTC 字体路径；空则按平台自动发现 |

Bot 回复不再按小时限制轮数，旧配置中的小时轮数上限会被忽略。每群每日 token 预算仍由 `dailyTokenBudget` 控制，按 Host 本地时间零点重置；并行上限、单 Bot 串行及讨论轮数等调度规则保持不变。

改动配置后需要重装/重启 bundle 层（`plugin_manager` 对已安装包需 remove→install 或重启）。

## 5. 数据、备份与恢复

- 数据在 `$DSH_HOME/storages/dsh-bot-team/`（groups / folders / bots / members / messages / discussions / tasks / conversations / session_bindings / meta）。单聊也是 `groups` 里的记录（`kind: "direct"`，一个 `botId` + 一个成员），自定义分组在 `folders` 表。
- Bot 的头像保存在 bot record 中：机器人头像用 `preset:<seed>`，插画头像用 `art:<id>`，自定义头像是压缩后的 `data:image/...`（256×256）。
- 自己的消息头像直接读取 DSH 登录账号的 `avatarUrl` 和昵称（Client 侧显示，不写入 Bot 数据）；未登录/无头像/加载失败时回退渐变字母。
- 群头像保存在 group record 的 `avatar` 字段：随机配色用 `preset:<seed>`，插画用 `art:<id>`，上传用 `data:image/...`。
- 文件数据在 `$DSH_HOME/dsh-bot-team/`：`bots/<botId>/BOT.md`（人格）、单聊工作目录 `direct/<botId>/`、群聊工作目录 `groups/<groupId>/`。群记录里的 `workspaceCwd` 可覆盖默认目录，留空即使用插件目录。
- Bot 的人格文件在 `$DSH_HOME/dsh-bot-team/bots/<botId>/BOT.md`（旧版 `SOUL.md`/`AGENT.md` 仍可被读取；保存一次后以 BOT.md 为准，可复制迁移）。
- Bot 会话是真实 DSH 持久后台记录，由插件直接管理 Agent，并挂载宿主默认 Agent preset。它们不进入 DSH 主会话列表。
- **历史会话整理**：已有 header 与日志保留。先前创建的普通 Bot 会话在空闲后自动归档；正在执行或目标仍激活时延后，不强制停止。下一次 Bot Team 执行改用后台会话，历史回复继续关联原日志。兼容当前配置的后台会话直接恢复。
- **存储目录迁移**：升级后首次启动会把 `storages/bot_team` 实体目录移到 `storages/dsh-bot-team`，旧路径成为指向新目录的兼容链接；新记录也写入新目录。迁移前先关闭存储，重启可重复执行。两边都已有实体目录或链接异常时会停止启动，保留两边数据，不自动合并。自定义 JSON 存储根目录时使用其实际路径。
- **备份**：停掉插件（或退出 DSH）后整目录复制 `storages/dsh-bot-team` 与 `dsh-bot-team/`；恢复时覆盖回去。`storages/bot_team` 只是兼容链接，无需作为第二份数据备份；缺失时启动会重建。
- **旧布局迁移（v0.8 / v0.8.1）**：首次启动新版本时，Host 把 `$DSH_HOME/bot-team/bots` 与仍位于 `$DSH_HOME/bot-team/` 下的工作目录迁到 `$DSH_HOME/dsh-bot-team/`，并改写对应群记录；v0.8.0 的 `<dataDir>/<botId>` 单聊目录会折进 `direct/<botId>`。外部自定义工作目录不动。迁移幂等，失败只记日志，下次启动会重试。迁移后旧 Bot 的 session cwd 与新工作目录不一致，首次回复时会为它新建 session（群消息历史保留，旧 session 文件不删）；手动修改群工作目录也会触发同样的重建。
- **schema 升级**：插件启动时自动跑 `meta/schema` 迁移（当前工作区 v8）；v6 给旧群补 `kind/folderId/order`，并为每个旧 Bot 生成确定性的单聊（`grp-dm-<botId>`）。v7 为每个聊天建立基线会话，将可信的当前/历史 session 绑定到所属段；保留原 session、消息和读取游标，升级本身不清记忆、不批量创建 Agent。v8 保留旧讨论的 classic 轮次与原消息，新建讨论/辩论使用 `protocolVersion: 2` 保存步骤和尝试，不从旧消息推造执行进度。domain 版本仍为 1，无需重建。升级前建议先备份。
- **讨论恢复**：崩溃恢复后，未结束的 v2 流程先进入 `paused`，读取原生执行状态后才能继续或重试；失败步骤需要重试，不会因「继续」而跳过。旧讨论保持经典兼容行为。恢复与原生忙状态边界见[讨论与辩论](<讨论与辩论.md#恢复与已知边界>)。
- **旧页面兼容**：加载新 Host 后刷新所有 Bot Team 页面。旧客户端的执行请求若缺少预期会话 ID，会收到 `reload-required`（HTTP 409）；已有草稿遇到其他窗口切换时收到 `stale-conversation`（HTTP 409），刷新状态后由用户明确采用草稿。只读历史继续可用，不会把旧请求静默发到新会话。
- **重置**：退出 DSH 后删除 `storages/dsh-bot-team` 及兼容链接 `storages/bot_team`；若还存在旧版单文件备份 `storages/bot_team.json`，也需移出存储根目录，避免宿主再次导入（会丢群/Bot/消息；Bot 会话文件可另行清理）。

## 6. 权限与安全

- 所有 HTTP 通道在 `/api` 登录态栅栏内，页面外无 Cookie 的请求 401。
- 所有 Bot 统一为全能力 Bot：文件读写、搜索、联网、命令执行；session 沙箱为 workspace-write。
- 可访问范围由群/单聊工作目录（`workspaceCwd`）限制：群默认 `$DSH_HOME/dsh-bot-team/groups/<groupId>/`，单聊默认 `$DSH_HOME/dsh-bot-team/direct/<botId>/`；只有旧记录缺少该字段时才回退 `defaultCwd`。同一个群里的 Bot 权限相同。
- Bot 的审批策略默认 `ask`：
  - 工作目录内、`workspace-write` 允许的文件读写与命令不需要审批，直接执行。
  - 越界写入、沙箱升权等需要审批的操作会显示待处理审批卡片；在 Bot Team 中选择「允许一次」或「拒绝」，结果同步回群。提问同样在 Bot Team 中回答；「查看日志 / 完整日志」始终只读。
  - `turnTimeoutMs` 默认 `0`，不设单轮执行时长上限；无人处理时会继续等待审批，也可手动停止执行。显式配置正数时仍按该毫秒数限制本轮执行，超时后审批标记为已取消。
  - 配置 `botApprovalPolicy: never` 可切换为无头模式：所有需要审批的操作一律拒绝（不是自动批准）。
  - 目录内的破坏性命令不会被审批拦截（只靠提示词约束），所以群工作目录要选对。
- 新 Bot 使用后台会话，继续对话、问题交互、审批均在 Bot Team 内完成。「查看日志 / 完整日志」提供独立只读审计与 JSONL 导出。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| 页面空白 / 看不到入口 | 刷新页面（⌘R）；确认插件已启用（插件管理页） |
| @ 了没反应 | 确认该 Bot 是该群成员且已启用；看右栏成员状态与错误提示 |
| 消息需要刷新才出现 | 曾出现在旧版本；当前版本 SSE 已修复，若复现请反馈 |
| `/new` 提示忙，已停止却仍不能新建 | 按提示检查后台作业、子代理、目标续跑、提问/审批或未执行输入，并等待收尾；停止回复不等于所有后台工作已结束，未知状态也会阻塞 |
| 提示「草稿已保留」 | 其他窗口已开始新会话；确认后点「将草稿用于当前会话」，再发送，原请求不会自动重试 |
| 升级后发送提示必须刷新 | 新 Host 已启用会话版本校验；刷新所有旧页面，加载匹配的新 Client |
| 新会话没有日志，旧日志是否丢失 | 本段 Agent 按需创建；用顶部「上一会话日志」或历史分隔处入口查看旧日志 |
| 讨论一直显示“进行中”或“暂停中” | 检查当前逻辑步骤是否还在执行、等待提问/审批或目标续跑；暂停会等该步骤完成。默认不设单轮时限，工具等待超时不会自动停止流程 |
| 已暂停却不能开始新讨论、`/new` 或切项目 | `paused` 仍是未结束状态；继续或重试完成它，也可提前收束或停止 |
| 已停止却仍显示 `stopping` | 原生作业、目标、子代理或输入队列尚忙或状态不明；等待并检查日志，再发新的停止操作检查收尾。重复同一 `requestId` 只返回既有结果 |
| 评审没有徽标 | 评审回复需以 `结论：通过/需修改` 开头（提示词已约束；可手动重试） |
| 悬停没有消息操作 | 确认鼠标停在气泡上（不是右侧空白）；触屏设备操作栏会常显 |
| 右键没有弹出菜单 | 若选中了文字或右键的是链接，会保留浏览器原生菜单；先点空白取消选中再右键 |
| 引用块点击没反应 | 原消息可能还没加载，先点顶部「加载更早的消息」 |
| 上翻时新消息没有自动滚到底部 | 这是 v0.6 的有意行为；点右下角「N 条新消息 / 回到底部」 |
| Bot 没有工具 / 不能写文件 | 所有 Bot 统一为全能力 Bot；检查群工作目录与 `botSandbox` 配置，确认目标文件在工作目录内 |
| 群里 Bot 读不了文件 | 确认群工作目录正确，且文件在目录内（所有 Bot 均具备文件读取能力） |
| + → 文件上传失败 | 检查单文件 ≤32 MB、每条消息 ≤10 个；确认 Host 已加载新版（上传路由与 `dsh-attachment`）；错误条会保留，点 × 移除后可重试 |
| Skill 选择器为空 | 当前工作区没有 `userInvocable` 的 Skill；把 `SKILL.md` 放到 `.dsh/skills/<name>/SKILL.md`、`.agents/skills` 或 `$DSH_HOME/skills`，并确认 Host 已重新加载 Bot 预设 |
| 选了 Skill 但 Bot 没按 Skill 执行 | 需要 Host 重新加载让 Bot 预设挂上 `tool-skill`；发送文本里保留 `/skill-name`（前后有空白/换行）；若 Skill 设了 `user-invocable: false` 则不会出现在选择器 |
| 报“额度已用完” | 本群达到 `dailyTokenBudget` 每日 token 预算；调整预算或等待 Host 本地时间次日零点，不再有每小时回复轮数限制 |
| 任务返工不可用 | 只有 `changes_requested` 状态可执行 `revise`；先通过 `bot_team_task_update` 要求修改，或等评审给出需修改 |
| 任务派发被阻塞 | 依赖任务尚未验收；先完成前置任务（或通过模型工具编辑依赖），依赖解除会自动通知 |
| 找不到任务面板 | 右侧任务面板已移除；任务通过 `bot_team_task_create/list/update` 或 HTTP action 管理 |
| 中断后任务还是 in_progress | 用 `bot_team_task_update` 的 `cancel` 中断任务，并通过 `bot_team_task_list` 核实状态；仅停止 Bot 回复不等于取消任务 |
| 评审后任务直接变为已验收 | 评审输出 `结论：通过` 会自动验收；如需人工把关，可不调用任务评审，检查交付后通过 `bot_team_task_update` 的 `accept` 手动验收 |
