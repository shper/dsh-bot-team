# Bot Team 使用指南

> 适用版本：`dsh-bot-team` 0.1.0（M1+M2+M3+M4 + v1.5.9 + v1.6.5 + v1.7 + v1.8），DSH Desktop 0.2.1-rc.x。
> 安装后刷新页面（⌘R），左侧栏点 **Bot Team** 图标进入工作台。

---

## 1. 核心概念

| 概念 | 说明 |
|---|---|
| **单聊** | 你与一个 Bot 的一对一会话；每个 Bot 创建后自动拥有，无需 @，有自己的消息时间线与会话记忆 |
| **群 / 话题** | 一个多 Agent 聊天室，有独立消息时间线、成员、工作目录与 token 用量 |
| **分组** | 左侧「群聊」里的自定义文件夹（一层），可折叠、可拖动排序；群只能属于一个分组，删除分组不会删除群 |
| **Bot** | 全局可复用的 Agent 定义：显示名、头像、模型、BOT.md。同一个 Bot 可加入多个群，每个群内是**独立会话与记忆** |
| **成员** | Bot 在某个群里的实例；有独立 `sessionId`（真实 DSH 会话），按 `origin:"subagent"` 不在左侧会话列表出现 |
| **工具权限** | 所有 Bot 默认全能力：文件读写、搜索、联网、命令执行；session 沙箱为 `workspace-write`，可访问范围由群工作目录限制 |
| **@ 提及** | 只有被 @ 的 Bot 会回复；一条消息可 @ 多个 Bot（并行回复） |
| **评审** | 对任意消息「请人评审」，评审者输出 `结论：通过/需修改`；可「让作者修改」 |
| **讨论** | 固定轮次的多 Bot 讨论（1–5 轮），可选结束总结（共识/分歧/待决） |
| **任务** | 指派给某个 Bot 的工作项：pending → 派发 → 交付 → 评审/验收 → 需修改返工；有验收标准、交付物、**优先级**与**依赖** |

## 2. 快速上手

> 左下角 **「Bot 管理」按钮** 是（全局）Bot 管理入口：查看全部 Bot、所属群，新建/编辑/删除全局 Bot。
> 界面已统一 UI 风格（v1.6.2）：弹窗分组表单、等宽栅格、粘性头尾；Bot 默认使用程序化机器人头像，可随机换配色/表情、选一套本地 SVG 插画，或上传自定义图片；自己的消息优先显示 DSH 登录账号头像；页面跟随 DSH 的浅色/深色主题；越界操作会在群时间线生成审批卡片。

1. 左侧栏 **Bot Team** →「单聊」右侧 **+** 新建 Bot，保存后会**自动打开它的单聊**；也可以先跳过 Bot，直接「群聊」右侧 **+** 建群（可填话题、工作目录）。
2. 群聊里右侧「+ 添加」拉入已有 Bot；没有 Bot 时点「+ 新建 Bot」创建。新建/编辑群时可设置群头像（随机配色 / SVG 插画 / 上传图片）。
   - 显示名（就是 @ 用的名字，需唯一）
   - 头像（默认按名称生成机器人头像；可随机换配色/表情、选插画或上传图片）
   - Provider / Model / Reasoning effort
   - 工具默认全开（文件读写 / 搜索 / 联网 / 命令），无需再选角色
   - BOT.md（人格 + 工作规范，一个文件；旧版 SOUL.md/AGENT.md 会自动合并读取）——保存后下一轮回复生效。
3. 群聊输入框输入 `@` 选择成员后发送；回复实时流式出现。单聊里直接发消息即可，不需要 @。
4. 更多操作：
   - 悬停消息 → 气泡侧边图标：**回复 / 复制 / 评审 / 修改 / 重试**；在消息上**点右键**也会弹出完整菜单（含「复制为引用」「定位原消息」），回复会带引用条，点击气泡里的引用块可跳回原消息
   - 群头部「讨论」→ 议题/成员/轮数/总结 → 右栏看进度，可「停止讨论」
   - 群头部「···」→ 添加成员 / 编辑群 / 导出 Markdown / 导出 HTML / 删除群
   - 成员卡片「查看会话」→ 打开该 Bot 自己的 DSH 会话
   - **任务板（v1.5.3 简化版）**：右栏「+ 新建任务」→ 填标题/描述/验收标准/指派 → 任务卡片「派发」；执行中可点「中断」立即停止该轮 Bot；点「执行流」直接打开该任务 Bot 的 DSH 会话查看完整执行过程
   - **依赖**：依赖的任务全部「已验收」后才能派发，未就绪时卡片显示「依赖未完成」（不会出现派发按钮）；前置任务验收后自动解除阻塞并写系统消息
   - **进阶（模型工具/API）**：评审、验收、要求修改、编辑、一键派发仍可用 `bot_team_task_update`（或 HTTP action）完成，UI 保持精简
   - 错误回复上「重试」；输入框底部「停止」中断当前群所有回复

### 单聊与分组（v1.7）

- **单聊置顶**：左侧「对话」栏固定「单聊」在上、「群聊」在下。每个 Bot 都有一行单聊（头像 + 名称 + 最后消息 + 时间），Bot 回复中显示绿点。
- **自动创建**：新建 Bot 后，Host 立即创建它的一对一会话并自动切过去；旧 Bot 在升级后也会由 schema v6 迁移补齐。单聊不能删除，删除 Bot 时会连同单聊与消息一起删除。
- **不需要 @**：单聊输入框没有「@ 提及」按钮，每条消息都直接发给该 Bot；单聊复用群聊的流式回复、停止、引用/复制/右键菜单、导出 Markdown 与 token 用量。评审、讨论、任务板是群聊专属流程，单聊里不提供（Host 也会拒绝）。
- **右侧面板**：单聊右侧显示 Bot 头像、provider/model、累计 token 用量，以及「编辑 Bot」「查看会话」；人格仍在「编辑 Bot → BOT.md」维护。
- **新建分组**：「群聊」标题右侧的文件夹图标（或群操作菜单里的「＋ 新建分组…」）；输入名称即可。分组名不可重复。
- **把群放进分组**：编辑群弹窗的「分组」下拉，或右键群 / 行尾「···」→「移动到分组」；也可以直接把群拖到分组标题上。
- **自定义排序**：拖动群可在分组内或跨分组排序；拖动分组标题可调整分组顺序；菜单里也有「上移 / 下移」。排序保存在 Host，刷新与其他页面一致。
- **展开/收起**：「单聊」「群聊」「未分组」和每个自定义分组左侧都有箭头，点击折叠/展开；状态存在浏览器 `localStorage`（`bot-team.sidebar.sections`），刷新保持。图标栏模式下不显示分组标题，按「单聊 → 群聊」顺序显示头像与分隔线。
- **删除分组**：分组内的群会回到「未分组」，不会被删除。
- **右侧面板收起**：聊天右上角的「面板」图标按钮，以及右侧面板标题栏的「»」，都能收起/展开成员 / 任务 / 讨论 / 单聊信息面板；收起后消息区变宽，按钮仍留在聊天头部用于重新展开。偏好存 `localStorage`（`bot-team.right-panel.collapsed`），刷新保持；窗口宽度 ≤1100px 时右侧面板本身会自动隐藏，切换按钮也隐藏。没有选中会话时（右侧 Bot 库）不提供收起。
- **旧 Host 提示**：如果只刷新页面、但没有重启 DSH / 重新启用插件，侧栏的单聊区会显示「Host 仍是旧版本」提示；这是 Host 模块尚未加载新代码，重启后自动恢复。v1.8 改名后插件 bundle 名变为 `dsh-bot-team`，必须完整重启 DSH（disable→enable 不够）。

### 左侧群栏收起（v1.6.5）

- 群栏头部 `群聊` 右侧的方形图标按钮用于收起侧栏（264px → 68px），再点「展开侧栏」恢复。
- 收起后只显示群头像：选中态淡蓝底、Bot 回复中的绿点仍在；鼠标悬停头像可看群名与最后一条消息。
- 头部只保留「展开侧栏」「+ 新建」两个图标，底部「Bot 管理」「设置」变为上下排列的图标，悬停提示含义不变。
- 偏好存在浏览器 `localStorage`（`bot-team.sidebar.collapsed`），刷新页面、切走再回来都会保持；存储不可用时仅当前会话生效。
- 键盘 `Tab` 到群头像后按 `Enter` / `Space` 可切换群；群栏宽度过渡在 `prefers-reduced-motion` 下关闭。

### 群聊信息流（v1.6）

- **分组与时间**：同一 Bot/人 5 分钟内的连续消息合并为一组，只在组首显示头像和名字；跨天或间隔 ≥5 分钟显示「今天 / 昨天 / 日期 + 时间」。
- **自己 / 他人**：自己在右侧蓝底气泡，其他成员在左侧白底气泡；头像在气泡外侧。
- **操作**：悬停任一消息，气泡侧边出现图标工具栏；在消息上点右键弹出同样的操作菜单（外加「复制为引用」「定位原消息」）。`回复` 会在输入框生成引用条，发送时写入原消息 `replyTo`。
- **右键菜单**：位置跟随光标并自动收进视口；方向键切换、Esc / 点空白 / 滚轮或触摸滑动关闭；选中文字后右键或右键链接时保留浏览器原生菜单。
- **滚动**：上翻阅读时新消息不会把你拉回底部，而是显示「N 条新消息 / 回到底部」；加载更早消息会保持当前阅读位置。
- **引用定位**：点击消息气泡里的引用块可滚动到原消息并高亮；原消息不在当前已加载范围时提示先加载更早消息。
- **输入**：输入框自动增高；`@` 选择器支持 ↑/↓ 选择、Enter 确认、Esc 关闭；底部显示正在回复的 Bot 数量与停止按钮。
- **头部**：群名、成员/话题摘要、「N 个回复中」状态；「讨论」为常用按钮，其余群操作在「···」菜单。
- **模型信息**：Bot 回复底部的模型名与 token 用量默认隐藏；悬停消息时显示，模型名提示里包含 provider / reasoning effort。

### 设置与关于（v1.7）

- 左侧栏底部 **设置** 打开 Bot Team 设置；弹窗是左侧模块导航 + 右侧内容，模块为 **消息设置**、**关于**。
- **消息设置**：原有「模型名称 / 输入 Token / 输出 Token / 平均回复速度」的悬停/常驻/隐藏设置整体移到这里；效果预览、恢复默认、取消、保存设置的行为不变。
- **关于**：显示插件说明与功能特性、版本号、包名和开发者；版本 / 包名 / 开发者来自 `bot-team/package.json`（由 Host bootstrap 的 `plugin` 字段下发，当前 `0.1.0` / `dsh-bot-team` / `shper`）。底部还列出数据目录和 BOT.md 位置。
- 左侧导航支持 ↑/↓/Home/End 切换，选中项有高亮与焦点环；「关于」页的底部按钮是「关闭」，不显示保存。

## 3. 模型工具（普通会话里可用）

在任意 coding session 里对主 Agent 说"建一个群让 A/B 讨论 X"，主 Agent 会调用：

| 工具 | 用途 | 关键参数 |
|---|---|---|
| `bot_team_list` | 列群/成员/最近消息 | `groupId?`、`includeMessages?` |
| `bot_team_create_group` | 建群 + 拉 Bot（缺的自动建） | `title`、`topic?`、`workspaceCwd?`、`bots[{name, provider?, model?}]` |
| `bot_team_send` | 发消息并返回回复 | `groupId`、`text`、`mentions[]`、`wait` |
| `bot_team_review` | 请某 Bot 评审并返回 verdict | `groupId`、`reviewer`、`messageSeq?`、`instructions?` |
| `bot_team_discuss` | 多轮讨论并返回 transcript/summary | `groupId`、`topic`、`members[]?`、`rounds?`、`summarize?` |
| `bot_team_task_create` | 建任务（可一步派发） | `groupId`、`title`、`assignee`、`reviewer?`、`priority?`、`dependsOn?[]`、`dispatch?`、`wait?` |
| `bot_team_task_list` | 任务列表（优先级排序） | `groupId`、`taskId?`、`status?`、`includeClosed?`、`limit?` |
| `bot_team_task_update` | 任务流转/编辑/一键派发 | `taskId`（dispatch_ready 时可省略）、`action`（dispatch/dispatch_ready/review/accept/request_changes/revise/cancel/update）、`groupId?`（dispatch_ready）、`wait?`、`force?` |

> Bot 成员自身被 deny 这组工具，避免递归调用。`enableModelTools: false` 可整体关闭。单聊是 UI 侧的一对一会话，不会出现在 `bot_team_list` 里；模型工具面向群聊。

## 4. 配置（`cordis.patch.yml` 的 `config`）

| 字段 | 默认 | 说明 |
|---|---|---|
| `dataDir` | `$DSH_HOME/dsh-bot-team` | 插件数据根目录（人格 + 工作目录） |
| `botsDir` | `<dataDir>/bots` | BOT.md（兼容旧 SOUL.md/AGENT.md）目录 |
| `defaultCwd` | Host 进程 cwd | 旧记录兜底；新群 / 单聊使用各自目录 |
| `migrateLegacyLayout` | true | 首次启动迁移旧的 `$DSH_HOME/bot-team` 布局 |
| `maxParallelTurns` | 3 | 群级并行回复上限 |
| `maxContextMessages` | 40 | 单轮注入历史消息上限 |
| `turnTimeoutMs` | 300000 | 单轮超时 |
| `maxTurnsPerHour` | 120 | 每群每小时 Bot 回复轮数上限 |
| `dailyTokenBudget` | 5000000 | 每群每日 token 上限 |
| `botSandbox` | true | 是否把 Bot session 显式设为 `workspace-write` 沙箱 |
| `botApprovalPolicy` | ask | `ask`：越界/升权时生成审批卡片并去 Bot 会话授权；`never`：直接拒绝所有需审批操作 |
| `autoDispatchReady` | false | 依赖解锁后是否自动派发变为就绪的任务 |
| `enableModelTools` | true | 是否暴露 `bot_team_*` 工具 |
| `toolWaitTimeoutMs` | 180000 | 模型工具等待超时 |
| `smokeTest` | false | 仅验证用：激活时跑端到端冒烟/恢复检查 |

改动配置后需要重装/重启 bundle 层（`plugin_manager` 对已安装包需 remove→install 或重启）。

## 5. 数据、备份与恢复

- 数据在 `$DSH_HOME/storages/bot_team/`（groups / folders / bots / members / messages / discussions / meta）。单聊也是 `groups` 里的记录（`kind: "direct"`，一个 `botId` + 一个成员），自定义分组在 `folders` 表。
- Bot 的头像保存在 bot record 中：机器人头像用 `preset:<seed>`，插画头像用 `art:<id>`，自定义头像是压缩后的 `data:image/...`（256×256）。
- 自己的消息头像直接读取 DSH 登录账号的 `avatarUrl` 和昵称（Client 侧显示，不写入 Bot 数据）；未登录/无头像/加载失败时回退渐变字母。
- 群头像保存在 group record 的 `avatar` 字段：随机配色用 `preset:<seed>`，插画用 `art:<id>`，上传用 `data:image/...`。
- 文件数据在 `$DSH_HOME/dsh-bot-team/`：`bots/<botId>/BOT.md`（人格）、单聊工作目录 `<botId>/`、群聊工作目录 `groups/<groupId>/`。群记录里的 `workspaceCwd` 可覆盖默认目录，留空即使用插件目录。
- Bot 的人格文件在 `$DSH_HOME/dsh-bot-team/bots/<botId>/BOT.md`（旧版 `SOUL.md`/`AGENT.md` 仍可被读取；保存一次后以 BOT.md 为准，可复制迁移）。
- Bot 会话是真实 DSH session（`$DSH_HOME/sessions/.../session-botteam-*`），由 DSH 持久化。
- **备份**：停掉插件（或退出 DSH）后整目录复制 `storages/bot_team` 与 `dsh-bot-team/`；恢复时覆盖回去。
- **旧布局迁移（v1.8）**：首次启动新版本时，Host 把 `$DSH_HOME/bot-team/bots` 与仍位于 `$DSH_HOME/bot-team/` 下的工作目录迁到 `$DSH_HOME/dsh-bot-team/`，并改写对应群记录；外部自定义工作目录不动。迁移幂等，失败只记日志，下次启动会重试。迁移后旧 Bot 的 session cwd 与新工作目录不一致，首次回复时会为它新建 session（群消息历史保留，旧 session 文件不删）；手动修改群工作目录也会触发同样的重建。
- **schema 升级**：插件启动时自动跑 `meta/schema` 迁移（当前 v6）；v6 会给旧群补 `kind/folderId/order`，并为每个旧 Bot 生成确定性的单聊（`grp-dm-<botId>`）。不改变 domain 版本，因此不需要重建。升级前建议先备份。
- **重置**：退出 DSH 后删除 `storages/bot_team`（会丢群/Bot/消息；Bot 会话文件可另行清理）。

## 6. 权限与安全

- 所有 HTTP 通道在 `/api` 登录态栅栏内，页面外无 Cookie 的请求 401。
- 所有 Bot 默认全能力：文件读写、搜索、联网、命令执行；session 沙箱为 workspace-write。
- 可访问范围由群/单聊工作目录（`workspaceCwd`）限制：群默认 `$DSH_HOME/dsh-bot-team/groups/<groupId>/`，单聊默认 `$DSH_HOME/dsh-bot-team/<botId>/`；只有旧记录缺少该字段时才回退 `defaultCwd`。同一个群里的 Bot 权限相同。
- Bot 的审批策略默认 `ask`：
  - 工作目录内、`workspace-write` 允许的文件读写与命令不需要审批，直接执行。
  - 越界写入、沙箱升权等需要审批的操作会在群时间线生成「审批请求」卡片；点「去审批」打开该 Bot 的 DSH 会话，选择「允许一次」或「拒绝」，结果会同步回群。
  - 无人处理时，本轮会一直等到 `turnTimeoutMs`（默认 5 分钟）超时；超时后审批标记为已取消。
  - 配置 `botApprovalPolicy: never` 可切换为无头模式：所有需要审批的操作一律拒绝（不是自动批准）。
  - 目录内的破坏性命令不会被审批拦截（只靠提示词约束），所以群工作目录要选对。
- Bot 的 `origin:"subagent"` 会话不出现在会话列表；「查看会话」用于调试。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| 页面空白 / 看不到入口 | 刷新页面（⌘R）；确认插件已启用（插件管理页） |
| @ 了没反应 | 确认该 Bot 是该群成员且已启用；看右栏成员状态与错误提示 |
| 消息需要刷新才出现 | 曾出现在旧版本；当前版本 SSE 已修复，若复现请反馈 |
| 讨论一直显示“讨论中” | 检查右栏是否有人运行中；可「停止讨论」；超时会自动停止 |
| 评审没有徽标 | 评审回复需以 `结论：通过/需修改` 开头（提示词已约束；可手动重试） |
| 悬停没有消息操作 | 确认鼠标停在气泡上（不是右侧空白）；触屏设备操作栏会常显 |
| 右键没有弹出菜单 | 若选中了文字或右键的是链接，会保留浏览器原生菜单；先点空白取消选中再右键 |
| 引用块点击没反应 | 原消息可能还没加载，先点顶部「加载更早的消息」 |
| 上翻时新消息没有自动滚到底部 | 这是 v1.6 的有意行为；点右下角「N 条新消息 / 回到底部」 |
| Bot 没有工具 / 不能写文件 | 所有 Bot 默认全能力；检查群工作目录与 `botSandbox` 配置，确认目标文件在工作目录内 |
| 群里 Bot 读不了文件 | 确认群工作目录正确，且文件在目录内（所有 Bot 默认可读） |
| 报“额度已用完” | 触发了 `maxTurnsPerHour` / `dailyTokenBudget`，调整配置或等待 |
| 任务「让作者修改」不可用 | 只有 `changes_requested` 状态可返工；先「要求修改」或等评审给出需修改 |
| 任务「派发」按钮置灰 | 依赖任务尚未验收；先完成前置任务（或编辑任务移除依赖），依赖解除会自动通知 |
| 任务面板没有评审/验收按钮 | v1.5.3 起 UI 精简为派发/中断/执行流；需要时用模型工具 `bot_team_task_update` 或 HTTP action |
| 中断后任务还是 in_progress | 中断以任务状态 cancelled 为准；若 UI 未刷新请刷新页面，或查看「执行详情」的最近错误 |
| 评审后任务直接变为已验收 | 评审输出 `结论：通过` 会自动验收；如需人工把关，评审后再点「验收通过」，或创建任务时选择“无评审者”改人工验收 |
