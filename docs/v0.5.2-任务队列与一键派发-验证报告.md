## 1. 新增能力

### 1.1 一键派发（批量）

- 服务动作 `task.dispatch_ready`：收集该群所有 `pending && ready` 任务，按 **priority → createdAt** 排序，
  逐个派发（最多 10，可配 `limit`）；返回 `{dispatched, skipped, queue, pendingReady}`。
- 每个任务仍走单任务派发同一路径：配额检查、状态置 `in_progress`、Engine 排队（受 `maxParallelTurns` 限制）。
- 失败处理：单任务失败记录到 `skipped`（配额错误立即停止后续派发），不会影响已派发任务。
- UI：任务面板显示「执行中 X · 排队 Y」，新增「一键派发 (N)」按钮（无就绪任务时置灰），完成后 toast 显示派发数量。
- 模型工具：`bot_team_task_update` 新增 `action: "dispatch_ready"`（需 `groupId`，可带 `limit`）。

### 1.2 队列可视化

- Engine 新增 `queueSnapshot(groupId)`：返回 `running/queued/parallelLimit/runningTaskIds/queuedTaskIds`；
- bootstrap 的每个 group 附带 `queue`；任务卡片在 `in_progress` 且位于排队区时显示「排队中（等待执行槽位）」，
  否则显示「Bot 正在执行…」；
- 队列长度由 Engine 既有调度器决定（`maxParallelTurns`，默认 3）。

### 1.3 自动派发（可选，默认关闭）

- 配置 `autoDispatchReady: false`：开启后，任务验收解锁依赖者时，自动派发所有变为 ready 的 pending 任务；
- 失败（配额/校验）只记 warn 并跳过，不影响验收本身；
- 冒烟校验默认关闭：依赖解除后任务保持 `pending` 且 `ready:true`，等待人工/模型派发。

## 5. 已知限制 / 后续

- 一键派发是「立即入队」，没有独立的待派发队列持久化；排队状态来自 Engine 内存（重启后丢失排队标记，任务仍是 in_progress，可重试/取消）；
- 自动派发默认关闭，且触发点只有「依赖解锁」，不覆盖「新建即 ready」；
- 无按任务并发的细粒度限制（仍受群级 `maxParallelTurns` 约束）；
- 完整 i18n 仍待后续；原「按 capability 精确收敛工具可见性」计划已取消，所有 Bot 统一全能力。
