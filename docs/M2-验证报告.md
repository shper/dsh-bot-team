## 1. 本轮新增能力

### 1.1 评审（review / revision）

| 能力 | 实现 |
|---|---|
| 请人评审 | 任意非系统消息 →「请人评审」→ 选评审者 +（可选）要求 → Host 写 review 请求系统消息 + 派发评审 turn |
| 评审提示词 | 内嵌**待评审原文全文** + 评审要求 + 固定输出格式（首行 `结论：通过` / `结论：需修改`）+ 最近上下文 |
| verdict 解析 | 回复完成后解析首行 → 写入 `message.meta.verdict = 'pass' | 'changes'`，UI 显示绿色「评审通过」/ 黄色「需修改」徽标 |
| 让作者修改 | 评审回复上出现「让作者修改」→ Host 定位原文作者（必须是 Bot 成员）→ revision turn（内嵌原消息 + 评审意见，要求输出完整修改版） |
| 消息模型 | `kind: review | revision` + `meta{reviewOf, revisionOf, reviewerMembershipId, instructions, verdict}`；UI 显示「评审 #seq」 |

### 1.2 多轮讨论（discussion）

| 能力 | 实现 |
|---|---|
| 发起讨论 | 「发起讨论」对话框：议题 + 成员多选 + 轮数（1–5）+ 是否总结 → `discussion.start` |
| 讨论状态 | 新表 `discussions`（per-record）：topic / memberIds / rounds / currentRound / currentIndex / currentSpeaker / status / summarize / startSeq |
| 串行轮次 | 确定性调度：每位成员发言 → `afterJobFinished` 推进 → 下一轮/下一位；一个讨论同时只有一个 turn；顺序 = 成员 order |
| 提示词 | 讨论 turn 注入议题 + 轮次 + 全部已有讨论发言，要求 ≤200 字、可同意/反驳、不重复；总结 turn 要求输出「共识 / 分歧 / 待决问题」 |
| 实时进度 | 每个 job 起止都广播 `discussion.updated`；右栏显示「第 x/y 轮 · 谁发言中」+ 停止按钮；消息带「第 N 轮」/「总结」徽标 |
| 停止 | `discussion.stop`：状态置 stopped、取消当前 turn、清空该讨论排队任务、广播 + 系统消息；`stopGroup` 同样会终止该群进行中的讨论 |
| 结束 | 正常结束写系统消息；可选总结作为最后一条消息（`meta.summary`），讨论状态 `done` |
| 崩溃恢复 | 加载时把 `running` 的讨论标为 `stopped(host-restart)`、`pending/streaming` 消息标为 error（可重试） |

### 1.3 配套打磨

- **Markdown 渲染**：标题/列表/编号列表/引用/行内代码/代码块/粗体/斜体/链接/分割线（无第三方依赖，纯文本兜底）。
- **历史分页**：首屏 120 条，「加载更早的消息」按 `beforeSeq` 上翻。
- **群 workspace 字段**：新建/编辑群可指定绝对路径工作目录（执行型 Bot 的 cwd）。
- **群 token 用量**：bootstrap 汇总每群 usage，右栏展示；单条消息保留 tokens 明细。
- **失败重试**：错误 Bot 消息上出现「重试」→ chat / review / revision 重新派发一轮（讨论单条不支持，需重开讨论）。
- **UI 埋点**：评审/讨论动作上报 `ui.report`（`kind:action`），补充真机验证证据。

## 3. 本轮发现并修复的缺陷

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| B4 | 带总结的讨论永远等不到“结束”（冒烟 `discussionRounds:false`、`settled:false`，UI 侧会一直显示讨论中直到超时） | 总结 job 完成后把 discussion 置 `done` 的分支没有调用 `settleDiscussionWaiters()`，等待者只能等 5 分钟超时 | 总结结束分支补 `settleDiscussionWaiters(discussionId)`；复测 `settled:true`、`status:done` |

> 说明：B4 是纯逻辑缺陷，只有“总结型讨论 + 等待结束”的路径能暴露，属于 M2 冒烟覆盖带来的价值。

  - UI 文案仍为中文硬编码（i18n 后续）。
