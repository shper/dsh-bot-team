# Bot Team 发布指南（DSH 插件）

> 范围：把 `bot-team/` 发布成别人可在 DeepSeek Harness（DSH）里安装的插件。
> 结论：代码本身已经是一个合规 bundle，缺的只是**发布元数据**与**分发入口**。推荐 **npm 公开发布**；Git 直装和市场索引是补充渠道。
> 校验环境：DSH `0.2.1-rc.3`（Desktop），Node `v26.10.0`，pnpm `11.28.5`。

## 1. DSH 插件的发布形态

DSH 的插件就是一个 npm 包，靠 `package.json` 的几个字段被识别和加载：

| 字段 | 本包取值 | 作用 |
|---|---|---|
| `dsh.bundle.patch` | `./cordis.patch.yml` | 安装后把哪些行插进 profile 组合（插件行 + Bot 全能力 preset） |
| `dsh.client` | `platform: web` / `immediately` / `inject` | Web 端 bundle 的声明 |
| `exports["./client"]` | `./client.js` | `window.__ModuleLoader__.load` 工厂，Host 侧按 `/plugins/<id>/client.js` 提供 |
| `exports["./locale/*.json"]` | `locale/{en,zh}.json` | 插件管理页的 `meta.title` / `meta.description` |
| `exports["./icon"]` | `./icon.svg` | 插件行/详情页图标（≤256 KiB，必须在包内） |
| `engines.dsh` | `^0.2.1-rc.3` | 安装前按运行中的 DSH 版本校验兼容性 |

所以「发布」= **`npm publish`**（主渠道）+ 可选的**市场索引 JSON**（发现渠道）。DSH 没有单独的「插件发布服务」，也不需要改 DSH 源码。

## 4. 路线 A：npm 公开发布（推荐）

### 4.1 发布前

```sh
cd bot-team

npm whoami                 # 未登录先 npm login
npm run check && npm test  # 118 条测试
npm pack --dry-run         # 确认文件清单：22 个、无 test/docs/本机路径

# 可选：真装一遍 tarball，确认包是完整的
npm pack --pack-destination /tmp/bt-check
mkdir -p /tmp/bt-check/app && cd /tmp/bt-check/app
npm init -y >/dev/null && npm install ../dsh-bot-team-1.0.0.tgz
node --input-type=module -e "const m = await import('dsh-bot-team'); console.log(m.name, m.inject)"
```

版本号遵循 SemVer：`1.0.0` 首发；发布前的内部迭代在 `docs/` 中记为 v0.5–v0.8.1。之后修 bug `1.0.1`，加功能 `1.1.0`，破坏性改动 `2.0.0`。

### 4.2 发布

```sh
cd bot-team
npm publish          # prepublishOnly 会自动跑 check + test
```

- 非 scope 包默认 public，`publishConfig.access: "public"` 已写上，防止账号默认私有；
- 若以后改用 scope（如 `@shper/dsh-bot-team`），必须同时改 `package.json.name` 与 `cordis.patch.yml` 里插件行的 `name`；
- 想带供应链证明：在 GitHub Actions 里用 OIDC 执行 `npm publish --provenance`（`repository` 已配置）。

### 4.3 用户怎么装

**桌面版（Web GUI）**：左侧 **插件 / Plugins** → 添加插件 → `dsh-bot-team@1.0.0`。装好后：

1. 安装完成后启用该 bundle；若安装前它已是启用状态，对 `bot-team` 行 **disable → enable**（或完整重启 DSH）——只刷新页面不会加载新的 Host 模块；
2. 浏览器刷新页面，左侧栏出现 **Bot Team** 图标。

**CLI / 其他 profile**：

```sh
dsh plugin --profile <profile> add dsh-bot-team@1.0.0
```

该命令在 profile 目录执行 pnpm 安装，成功后 `reconcile` 会把新 bundle 自动追加到 `dsh.profile.bundles`（若包没有 `dsh.bundle` 则只作为普通依赖并给出警告）。

**Agent 代装**：`plugin_manager` 的 `install_bundle`，`target` 填 `dsh-bot-team@1.0.0`；安装类操作需要审批。

### 4.4 升级

- 桌面版：插件页提供 **Update** 时直接更新（内部是 remove → install）；没有 Update 时先 Remove 再按新版本重新添加；
- 或 `plugin_manager remove_bundle` → `install_bundle target: dsh-bot-team@<新版本>`；
- 或 `dsh plugin --profile <profile> add dsh-bot-team@<新版本>`。

升级 Host 代码后必须重新加载（disable→enable / 重启）；只刷新浏览器只会拿到旧 Host + 新 Client，页面会出现「Host 仍是旧版本」。

## 5. 路线 B：Git 直装

不想等 npm 时，可直接装某个 commit：

```sh
git+https://github.com/shper/dsh-bot-team.git#<40 位 commit>&path:/bot-team
```

- `install_bundle` 会先用 `git ls-remote` 检查仓库可达性（5 s 超时），再交给 pnpm；
- 装的是 commit 快照，不会自动跟随 `main`，升级要换 commit；
- 包内没有 `prepare`/`postinstall` 构建脚本，不存在 pnpm 拦构建脚本的问题；
- GitHub 仓库已是公开的 `shper/dsh-bot-team`（包在 `bot-team/` 子目录，所以必须带 `&path:/bot-team`）。

## 6. 路线 C：插件市场索引（可选的发现层）

DSH 的 **Discover** 页由 `dsh-plugin-market` 读「用户自己配置的索引 URL」，格式为 **format 1** 的 JSON。注意两点：

- 默认没有任何索引源；且该能力在实验性 bundle `dsh-experimental-plugin-market-bundle` 里，默认未启用。所以市场索引只是**额外的曝光渠道**，不能替代 npm；
- 索引只描述包，不校验包是否真的存在；版本、发布时间要与 npm 实际发布同步。

把下面 JSON 托管到任意 HTTPS 地址即可（`raw.githubusercontent.com` 或 GitHub Pages 最省事）：

```json
{
  "format": 1,
  "title": { "en": "shper DSH plugins", "zh": "shper 的 DSH 插件" },
  "metadata": {
    "categories": {
      "chat": { "title": { "en": "Multi-agent chat", "zh": "多 Agent 对话" } }
    }
  },
  "plugins": [
    {
      "name": "dsh-bot-team",
      "title": { "en": "Bot Team", "zh": "Bot Team 群聊与单聊" },
      "description": {
        "en": "Single chats and multi-agent group chat: every bot gets a direct chat, groups live in collapsible folders, and bots get their own model, persona and full tools.",
        "zh": "单聊与多 Agent 群聊：每个 Bot 自动拥有单聊，群聊可分组折叠，Bot 有独立模型、人格与全能力工具。"
      },
      "icon": "../bot-team/icon.svg",
      "author": "shper",
      "homepage": "https://github.com/shper/dsh-bot-team#readme",
      "repository": { "url": "https://github.com/shper/dsh-bot-team.git", "directory": "bot-team" },
      "metadata": {
        "category": "chat",
        "keywords": ["dsh", "plugin", "bot", "multi-agent", "group chat", "单聊", "群聊"]
      },
      "versions": [
        {
          "version": "1.0.0",
          "publishTimestamp": 1793026389,
          "source": { "type": "npm" },
          "engines": { "dsh": "^0.2.1-rc.3" }
        }
      ]
    }
  ]
}
```

若放在 `https://raw.githubusercontent.com/shper/dsh-bot-team/main/market/index.json`：

- `icon` 写成相对路径 `../bot-team/icon.svg` 会解析成 `.../main/bot-team/icon.svg`，必须是 https（该条已满足）；
- `publishTimestamp` 是 Unix **秒**，填 npm 实际发布时间；
- 每发一版就追加一个 `versions[]` 条目（`source.type: "npm"` 时不需要写 registry，用户配置的 registry 优先）；
- 用 Git 源时改成：`"source": { "type": "git", "url": "https://github.com/shper/dsh-bot-team.git", "commit": "<40 位小写 commit>", "path": "bot-team" }`。

用户侧：启用市场 bundle 后，在 **设置 → 插件 → Discover** 添加该索引 URL，即可搜索并安装；`marketInstallTarget` 会生成 `dsh-bot-team@1.0.0` 作为安装 target。

## 7. 版本兼容与 DSH 升级

DSH 的兼容性检查（`evaluatePluginCompatibility`）语义：

- 有 `engines.dsh` 时**只看它**，忽略 `peerDependencies`；范围按 `includePrerelease: true` 计算；
- 没有 `engines.dsh` 时退化为检查所有 `@deepseek-ai/dsh*` peer 依赖。

本包选择 `^0.2.1-rc.3` 的实际效果：

| DSH 版本 | 结果 |
|---|---|
| `0.2.1-rc.3` / `0.2.1` / `0.2.2-rc.1` | 通过 |
| `0.3.0-rc.1` 及以后 | 拒绝，需显式豁免 |

DSH 仍处于 `0.2.1-rc.x` 快速迭代期。升级 DSH 后建议：

1. 跑 `node --test bot-team/test/*.test.js` 和 [`docs/升级检查清单.md`](./升级检查清单.md)；
2. 确认兼容再把 `engines.dsh` 放宽（如 `^0.3.0-rc.1`）并**发新版本**——不要直接改已发布版本的 range；
3. 用户临时被拦时可用 exact-version exemption：

```sh
dsh plugin --profile <profile> allow-version dsh-bot-team@1.0.0 --dsh-version <精确版本> --accept-risk
```

桌面版用 `plugin_manager` 的 `set_version_exemption`（需 `acceptRisk: true`，并先向用户说明风险）授权，CLI 用上面的命令。豁免只对「精确包版本 + 精确 DSH 版本」生效，DSH 再升级就失效。

## 9. 发布前值得处理的已知风险

| 风险 | 影响 | 建议 |
|---|---|---|
| `client.js` 硬编码 `ACCOUNT_CLIENT_VERSION = '0.2.1-rc.3'` | DSH 升版后 `account.getProfile` 可能拒绝，自己的消息头像回退渐变字母 | 改为由 Host bootstrap 下发版本，或探测失败再回退 |
| UI 文案全中文（i18n 未做） | 英文用户可用性差 | 至少把插件页 `locale/en.json` 与 README 英文段落做完整 |
| `dsh.client.inject` 列了 layout/sidebar，但 client 只 `require('react')` | 仅影响激活排序，无功能问题 | 可保留（合法），也可删掉减少耦合 |
| Bot 默认全能力 + `workspace-write` | 公开分发后用户会执行任意命令，安全预期要讲清楚 | README 显著说明沙箱范围、`botApprovalPolicy` 审批策略与配额 |
| 数据契约已固化（`storageDomain: bot_team`、`bot_team_*` 工具名、`/api/bot-team.*`、`$DSH_HOME/dsh-bot-team`） | 发布后改名会造成数据迁移负担 | 保持稳定；变更必须写迁移 |
| 没有 CI | 发布依赖本机手动跑测试 | 加 GitHub Actions：`node --test` + `npm publish --provenance` |
| 版本号与 DSH 版本耦合 | DSH 大改时插件需要跟版 | 在 README 标注「适配 DSH 0.2.1-rc.3」并维护兼容表 |
