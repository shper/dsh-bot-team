# Bot Team 发布与维护指南

仓库根目录就是 `dsh-bot-team` 的 npm 包目录，配置与接口说明见[配置与接口](<配置与接口.md>)。版本以 [包清单](<../package.json>) 为准；源码版本不代表该版本已发布到 npm。发布说明应明确区分已发布能力与工作区开发改动。

## 包结构与元数据

DSH 使用 npm 包中的声明加载 Host 与 Client：

| 字段 | 本包约定 |
|---|---|
| `name` | `dsh-bot-team` |
| `dsh.bundle.patch` | `./cordis.patch.yml`，提供插件与 preset 声明 |
| `dsh.client` / `exports["./client"]` | Web Client 声明与单文件入口 |
| `exports["./locale/*.json"]` / `exports["./icon"]` | 插件管理页的标题、描述与图标 |
| `engines.dsh` | `^0.2.1-rc.3`，按实际验证过的宿主版本维护 |
| `dependencies.fontkit` | PDF 字体子集化的运行时依赖 |

[发布文件白名单](<../package.json>) 包含 Host、Client、bundle patch、locale、图标、许可证、[根 README](<../README.md>) 和 [CHANGELOG](<../CHANGELOG.md>)；测试、仓库文档、临时输出及本机数据不随 npm 包发布。其中指向仓库文档与图片的链接应使用可公开访问的完整 URL，避免安装后引用包外文件。包位于仓库根目录，包清单不设置 `repository.directory`。

## 本地开发与验证

从仓库根目录执行：

```sh
npm install
npm run check
npm test
npm pack --dry-run
```

普通 Node 会按环境跳过安装版宿主契约测试；PDF 用例也受系统字体条件影响。涉及 Agent 生命周期、会话归属、目标、后台作业或子代理的改动，还需按[后台会话与完整日志](<原生会话与完整日志.md#验证与加载>)运行安装版契约测试。以本次实际输出记录验证结果，不把历史通过数作为当前验收结果。

安装本地源码时，在插件管理页添加仓库根目录 `/path/to/dsh-bot-team`，并先在该目录安装运行时依赖。Host 代码更新后重新启用插件（disable → enable）或重启 DSH，然后刷新现有页面；只刷新浏览器不能替换 Host。变更 bundle patch 或 preset 声明时，需重装 bundle 或完整重启以重新应用组合。

## npm 发布

1. 按 SemVer 确定版本，保持[包清单](<../package.json>)、[根 README](<../README.md>)、[配置与接口](<配置与接口.md>)与界面「关于」一致。修复升 patch，兼容功能升 minor，破坏性变更升 major；将 [CHANGELOG](<../CHANGELOG.md>) 中本次纳入的「未发布」条目移至对应版本，记录日期与必要的升级说明，其他开发中改动继续保留在「未发布」。
2. 运行上述检查，查看实际打包文件；有需要时生成 tarball 并安装到临时目录，确认 `import('dsh-bot-team')`、Client、locale、图标和 patch 均可解析。
3. 在仓库根目录确认 npm 身份，再发布：

```sh
npm whoami
npm publish
```

`prepublishOnly` 会执行语法检查和测试，`publishConfig.access` 为 `public`。若使用 GitHub Actions 与 OIDC，可执行 `npm publish --provenance`。npm 发布成功后再更新安装示例和可选市场索引中的公开版本信息。

## 安装与升级

桌面版在 **插件 / Plugins → 添加插件** 填 `dsh-bot-team@<已发布版本>`。CLI 对应：

```sh
dsh plugin --profile <profile> add dsh-bot-team@<已发布版本>
```

Agent 工具的入口是 `plugin_manager` 的 `install_bundle`，`target` 同上。插件页提供 **Update** 时可直接更新；否则移除旧 bundle 后添加新版本。安装或升级后重新加载 Host，再刷新页面。使用独立测试 profile 检查安装、启动、入口、健康接口、存储及升级兼容，步骤见[升级检查清单](<升级检查清单.md>)。

Git 直装应固定到包含新目录布局的提交：

```text
git+https://github.com/shper/dsh-bot-team.git#<40 位 commit>
```

Git 安装使用提交快照，不自动跟随 `main`；升级时更换 commit。当前包位于仓库根目录，Git 直装地址无需子目录 `path`，包清单也不设置 `repository.directory`。历史提交若仍使用旧布局，应按那个提交的实际目录安装。

## 可选的插件市场索引

市场索引是发现渠道，实际分发仍由 npm 或 Git 完成。宿主启用 `dsh-experimental-plugin-market-bundle` 后，用户可在 Discover 中添加索引 URL；不能假设默认已有索引源。

format 1 索引需维护这些字段：

| 字段 | 约定 |
|---|---|
| `name` | `dsh-bot-team` |
| `title` / `description` | 中英文插件介绍 |
| `icon` | 可访问的 HTTPS 图片地址 |
| `repository.url` | 仓库 URL；包位于仓库根，不设置 `repository.directory` |
| `versions[].version` | 实际已发布的版本 |
| `versions[].publishTimestamp` | npm 实际发布时间，Unix 秒 |
| `versions[].source` | npm 使用 `{ "type": "npm" }`；Git 需提供 URL、40 位 commit，并按目标宿主的市场索引规范在 `source.path` 指定仓库根目录 |
| `versions[].engines.dsh` | 与该版本包清单一致 |

如索引位于仓库的 `market/index.json`，相对图标地址可为 `../icon.svg`，部署后需验证它解析为有效 HTTPS 地址。索引不会替你验证包是否存在，不要提前填写尚未发布版本的时间。

## DSH 兼容与数据维护

宿主优先检查 `engines.dsh`，按包含预发布版本的范围计算；没有该字段时才退回检查 DSH peer 依赖。当前 `^0.2.1-rc.3` 接受 `0.2.1-rc.3`、`0.2.1`、`0.2.2-rc.1`，不接受 `0.3.0-rc.1` 及以后。

升级 DSH 后先运行回归与[升级检查清单](<升级检查清单.md>)；确认兼容后再放宽范围并发布新插件版本。临时 exact-version exemption 只对指定包版本和指定宿主版本生效，不替代兼容验证：

```sh
dsh plugin --profile <profile> allow-version dsh-bot-team@<插件版本> --dsh-version <宿主精确版本> --accept-risk
```

源码移到仓库根目录不会改变以下公开或持久契约：storage domain `bot_team`、模型工具 `bot_team_*`、HTTP `/api/bot-team.*`、bundle 行 ID `bot-team` 和运行时数据目录 `$DSH_HOME/dsh-bot-team`。变更这些契约需单独设计兼容与迁移。

涉及持久格式变更时，停止插件后备份 `$DSH_HOME/storages/dsh-bot-team` 与 `$DSH_HOME/dsh-bot-team/`；`storages/bot_team` 是兼容链接。会话切换与历史绑定的维护约束见[新建会话](<新建会话.md>)；备份、恢复和旧布局迁移见[使用指南](<使用指南.md#5-数据备份与恢复>)。

## 发布检查清单

- [ ] 语法、测试和必要的安装版宿主契约通过；记录本次环境与条件跳过原因。
- [ ] 打包文件完整，无测试、临时数据、凭据或本机路径；tarball 可安装并解析入口与依赖。
- [ ] 版本、兼容范围、源码目录和 README 链接一致；包外文档与图片使用公开 URL。
- [ ] 独立 profile 中验证入口、认证健康接口、旧数据读取及 Host/Client 更新。
- [ ] PDF 在目标平台能发现 CJK 字体；无字体时返回 501，可配置 `pdfFontPath`。
- [ ] npm 发布后再更新公开安装示例和可选市场索引。
