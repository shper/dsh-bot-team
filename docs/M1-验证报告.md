### 2.5 本轮发现并修复的缺陷（真机验证驱动）

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| B1 | 群消息列表恒为空（`messages-loaded count=0`） | `beforeSeq/afterSeq` 缺省时 `Number(null)=0` 被当成有效过滤条件，`seq < 0` 过滤掉全部消息 | 参数解析改为 "空/非法 → undefined"，仅在显式传入时过滤 |
| B2 | 有新消息不会自动出现（只能刷新） | SSE handler 里 `ReadableStream.start()` 的 `this` 是 underlying source 而不是 Service，`this.bus.subscribe` 抛错 → EventSource 一直失败 | 捕获 `const self = this` 后再用 `self.bus/repo/engine`（错误会记录到 smoke 日志） |
| B3 | @ 成功后偶发看不到新消息 | 发送成功后只刷新了 bootstrap，没有重新拉取消息；SSE 重连后也没有补偿 | 发送/停止后触发 messagesTick 重拉；SSE `hello` 时自动重拉一次做 gap 补偿 |

> 说明：B2 的定位依靠 Host 侧 `debug/sse-error` 埋点（含 stack），证明"真实页面连不上 SSE"——这正是 M1 阶段必须真机验证的原因。

## 3. 实现要点（与设计文档对应）

- **群/话题**：`groups`；创建/编辑/删除；每群独立 workspaceCwd（默认 Host cwd，可配）。
- **全局 Bot 库**：`bots` 为全局实体（名字唯一，名字即 @ 提及词）；每个群通过 `members` 引用，成员持独立 `sessionId` → 独立记忆。
- **每 bot 独立模型**：创建时 `agentOptions`；`resume` 时复传（M0 P2）；模型目录来自 `sessionController.modelCatalog()`，UI 下拉可用。
- **人格**：setup 内注册 `deployment:persona-prefix`（覆盖部署人格）+ `bot-team:group` runtime context；文件编辑后下一轮生效（每轮 `personas.refresh`）。
- **能力档**：讨论型挂 `bot-team-basic`（无工具）；评审/执行挂 `bot-team-tools`，评审额外 deny `write/edit/bash`；两种档位都 deny Team 工具（避免 runtime-root bot 变成 Team Lead 干别的事）。
- **编排**：多 @ 并行（默认上限 3）；占位消息保证时间线稳定；`assistant-stream` 增量 → `message.delta`，每步 `assistant/message` → `message.replace` 纠偏，`turn/end` 收尾（done/error/stopped）；停止=取消运行中 turn + 清队列；超时同理。
- **传输**：exact Fetch 路由 + SSE；全部在 `/api` 登录态栅栏内（M0 已验证）。
