# v0.5.3 任务面板简化 + 中断 / 执行详情 — 验证报告

> 状态：**✅ 完成**。根据反馈把任务面板从"多按钮工作流"简化为「派发 / 中断 / 执行详情」，
> 并实现真正的**进行中中断**（abort 当前 Bot turn）与**一键打开执行流**（直接打开指派 Bot 的 DSH 会话）。
> 真机 UI 由用户确认正常。
>
> 证据：`.bot-team/smoke.jsonl`、`~/.dsh/storages/bot_team/tasks`、真实工具调用记录。

---

## 1. 用户反馈与取舍

原任务面板每张卡片最多 6 个按钮（请评审/验收通过/要求修改/取消/编辑/一键派发），信息密度过高。
新目标：**任务只要三件事** —— 能派发、进行中能中断、能看执行详情。

因此本轮：

| 变化 | 说明 |
|---|---|
| 移除 UI 按钮 | 请评审、验收通过、要求修改、让作者修改、编辑、一键派发、面板队列计数全部从 UI 移除 |
| 保留能力 | 上述动作仍保留在 **HTTP action / 模型工具**（`bot_team_task_update`）中，需要时由模型或 API 驱动 |
| 任务卡片 | 状态徽标 + 标题 + 指派/状态提示 + 依赖未完成提示；动作仅「派发」「中断」「执行流」 |
| 新建任务 | 精简为：标题、描述（可选）、验收标准（可选）、指派给 |

## 2. 新增/变更

### 2.1 进行中中断（真正的 abort）

- `task.cancel` 在任务 `in_progress` 时：
  1. 先把任务状态置为 `cancelled` 并持久化；
  2. 调用 Engine 新增的 `cancelTaskRun(taskId)`：对 running 中的该任务 job 执行 `abortJob`（取消 Agent turn），
     并移除该任务的排队 job；
  3. 返回 `interruption: {aborted, dequeued}`（同时暴露在模型工具输出中）。
- 任务 hook 守卫：已取消的任务不会被中断 turn 的「失败回写」覆盖回 `in_progress`。
- UI：卡片在 `in_progress` 时显示「中断」按钮（红色），点击后 toast「已中断任务」并刷新。
- 模型工具验证：创建长任务 → `dispatch wait:false`（返回 `running:true`）→ `cancel` → 任务 `cancelled`、
  无交付物、revision 0、LLM 不再继续输出。

### 2.2 执行流（一键直达）

- 任务卡片「执行流」按钮：直接打开该任务**指派 Bot 的 DSH 会话**（即截图中的执行流：步骤、工具调用、耗时等完整过程），
  不再经过中间弹窗；指派成员缺失时给错误提示。
- 任务的关键结果（交付物/评审）仍在群消息里；需要看"如何执行"就点「执行流」。

## 3. 验证

### 3.1 真实工具调用（主会话 Agent）

| 步骤 | 结果 |
|---|---|
| `bot_team_task_create`「验证：中断长任务」 | pending ready |
| `bot_team_task_update dispatch wait:false` | `status:in_progress`, `running:true` |
| `bot_team_task_update cancel` | `status:cancelled`；`interruption:{aborted:1,dequeued:0}` |
| 6 秒后 `bot_team_task_list includeClosed` | 仍 `cancelled`，无 deliverable、revision=0（未继续交付） |

### 3.2 回归

- 后端 `smoke-v9` 23/23 的检查项均在 v0.5.2 时通过；本轮只改 UI 与 cancel 附加行为，
  `task.cancel` 对 pending/delivered 的行为保持不变（无 interruption 字段）。
- 中断实现有 hook 守卫 + Engine abort，无宿主崩溃（无新增 crash 日志）。

### 3.3 真机 UI

由用户确认：面板变简洁（仅派发/中断/执行流）、点击「执行流」可直接打开 Bot 会话、中断生效。

### 3.4 本轮修复的 UI 缺陷

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| S3 | 点「执行详情」无反应/报错 | 组件里引用了未从 props 解构的 `onTaskDetail`（ReferenceError）。 | 该弹窗被「执行流」直连取代；顺便移除未使用的 props 与组件。 |

## 4. 演示数据（不变）

M1 冒烟测试群保留 4 个演示任务（3 个可派发 + 1 个被依赖阻塞），用于体验「派发 → 执行中 → 中断 / 执行详情」。

## 5. 已知限制 / 后续

- UI 不再提供评审/验收/编辑/一键派发；这些能力保留在模型工具与 HTTP action 中（避免面板复杂化）。
- 「执行流」打开的是 Bot 的完整会话（包含历史任务上下文），不是只过滤当前任务；任务级结果看群消息。
- 中断是"尽力而为"：若供应商请求已结束或 turn 正在收尾，abort 可能只终止后续步骤；任务状态始终以 cancelled 为准。
