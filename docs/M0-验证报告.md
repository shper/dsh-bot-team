## 2. 已证明的机制（实现方案可以放心依赖）

1. **整页 + 侧栏入口**：`sidebar.panellist` 注册即出现入口，点击调用 `ctx.layout.selectPanel(id)`；`main` 是 keyed 全局面板，注册同 key 即成为一整页；`main` 页面的标准 props 里带 `useSessions`/`usePanelInfo`/`useSessionStatus` 等 hook（正式插件可直接读 bot session 的 projection）。
2. **零代码生成的 Client→Host 通道**：`ctx.connection.fetch.register()` 注册的 `/api/bot-team-spike.*` 路由在页面内可直接 `fetch()`（`HttpOnly` Cookie 自动携带），无 Cookie 时 401；**SSE 可用**，服务端主动断开后浏览器 `EventSource` 自动重连。写接口 POST JSON、读接口 GET、实时 SSE 的整套方案成立。
3. **插件自有 domain**：`ctx.storageDomain.open(spec)` 可用；写穿磁盘后 `put/get/update/delete` 与 `domain/changed` 事件正常；插件重载后能重新打开同一 domain 并读回数据（磁盘路径在 `~/.dsh/storages/<domain>/`）。
4. **Bot = 真实 agent**：`ctx.agents.create({ sessionId, meta:{cwd,origin:'subagent'}, agentOptions:{provider,model}, setup })` 全流程可用；非默认模型生效（日志 `request/header` 可证）；`setup` 中注册的 `deployment:persona-prefix` 同名 section **成功覆盖部署人格**；`approval/policy=never` 落盘；回复可从 `session/event` 的 `assistant/message` + `turn/end` 捕获；`handle.dispose()` 后 `agents.resume()` 能继续对话（历史连续）。
5. **bot 会话可隐藏**：session header 落盘 `origin:"subagent"`（侧栏隐藏逻辑已在 client 源码中核实），且 `parentSession` 可以缺省不出问题（至少创建/运行/dispose/resume 全程无异常）。
6. **开发迭代方式**：profile 插件 `disable → enable` 能重新加载修改后的 Host 模块代码（无需重启 App）；但**替换已安装包（install_bundle）不行**（返回 `already-installed`；workspace 链接目录的文件改动靠 reload 生效）。

## 3. M0 抓到的真问题（已修复，正式实现必须遵守）

| # | 问题 | 现象 / 根因 | 修复 / 正式方案要求 |
|---|---|---|---|
| P1 | `agent.followup()` 必须传**完整 UserMessage** | 传 `{content, source}` 会写入缺 `role`/`id` 的 `user/message`；LLM 报 `messages[1]: missing field 'role'`（422），且 session 重新打开时报 `event at seq N lacks an identified message`（**日志损坏、无法 resume**） | 手动构造 `{ role:'user', id: randomUUID(), content, source:{kind:'user'} }` 再 `followup`（M0 已验证）；正式插件必须走同一个消息工厂函数 |
| P2 | `agents.resume()` **不继承** session 里的 provider/model | resume 后 turn 直接报 `agent has no provider/model: set AgentOptions.provider and AgentOptions.model` | 持久化每个 bot 的模型路由，**每次 resume 都重新传 `agentOptions`**（或 `agent/request` 瀑布 pin） |
| P3 | domain per-record key 必须 path-safe | key 含 `.` 时抛 `per-record key 'state.last-bot' is not path-safe (must match /^[a-zA-Z0-9_-]+$/)` | 消息/记录 id 用安全字符：编号 `msg-000123`、ULID（连字符）等；**不要用 `:`/`.`/`/`** |
| P4 | setup 内 `assemble()` 看不到刚注册的 persona 覆盖 | setup 阶段 `systemPrompt.assemble()` 返回的 `deployment:persona-prefix` 仍是部署版（但**真实请求**的 system/message 已是覆盖版） | 人格是否生效要断言 **durable session log 的 system/message** 或真实请求，不要在 setup 里 assemble 断言 |
| P5 | runtime root 的 bot 会继承 profile 级 Agent Teams 身份/工具 | 系统提示出现 "Agent Teams is available…You are the Team Lead"；工具表里含 `spawn_teammate/list_agents/send_message` 等（`tool-agent-team` 是 host 平面行） | 正式插件必须在 bot 的 `setup` 里 `tools.restrict({deny:[...]})`，必要时 `systemPrompt.suppressRuntimeContext()` 或让 bot 成为运行时子级 |
| P6 | 权限策略变化会写入 bot session | 设置 `approval=never` 产生 `approval/policy` 事件（正常，但要知道） | 无（记录在案的预期行为） |
| P7 | 插件安装后 host 半更新 | `install_bundle` 对已安装包返回 `already-installed`；改代码后必须 `disable→enable`（或重启） | 正式开发流程：workspace 链接 + reload 迭代；发版再走 install_bundle |

> P1 的旧损坏 session 文件仍留在 `~/.dsh/sessions/--…bot-team-spike--/session-spike-fc3ce50d…`（首轮产物），与当前验证无关，卸载 spike 时可清理。

## 5. 对正式方案的影响（已回写到设计文档）

- 正式插件需要新增一个 `createBotUserMessage()` 工厂（P1）、持久化并复传模型路由（P2）、id 生成规则（P3）。
- 人格生效的验收标准改为"读 session log 的 system/message"（P4）。
- Bot 工具面必须在 setup 中显式收敛（P5），并把"bot 作为 runtime root 会继承 profile 级工具/身份"写进风险表。
- 传输层结论不变（fetch route + SSE 已验证），可以放心作为正式方案的 Client↔Host 通道。
