## 1. 本轮内容（设计文档 M4 范围 + M3 遗留硬化）

### 1.1 Domain schema 版本与迁移

- 新增 `SCHEMA_VERSION = 2` 与 `repo.runMigrations()`：**domain 版本保持 1**（避免 storageDomain 的 `version-mismatch` 拒绝打开），
  数据形态版本记录在 `meta/schema`，逐条迁移并持久化，可顺序追加后续迁移步骤。
- v1 → v2 迁移内容：补齐消息 `kind/meta/status/usage` 默认值、讨论 `currentRound/currentIndex/summarize` 默认值，
  写回 `{ version: 2, migratedAt }`。
- 实测：旧库（124 条消息 / 5 个讨论）打开时自动迁移，`meta/schema.json` 记录 v2；`smoke-v6` 的 `schemaVersionMigrated=true`。

### 1.2 配额与限流（按群）

| 配置 | 默认 | 说明 |
|---|---|---|
| `maxTurnsPerHour` | 120 | 每群最近一小时 Bot 回复轮数上限 |
| `dailyTokenBudget` | 5,000,000 | 每群每日 token 用量上限 |

- `service.checkQuota(groupId, turns)` 基于消息时间与 usage 统计（当日 token、近 1 小时轮数）。
- Engine 在 **@ 派发 / 评审 / 让作者修改 / 重试 / 发起讨论 / 讨论每个轮次调度** 前检查；超限抛 `quota` 错误（UI 显示可读原因），
  讨论中途超限会停止讨论并写入系统消息（`stopReason='quota'`）。
- 模型工具（`bot_team_send/review/discuss`）走同一路径，超限返回同样错误。
- `health.quotas` 暴露每群当前用量；冒烟同时验证「允许」与「拒绝超限」两条路径（`quotaWithinLimits` / `quotaRejectsOverLimit`）。

### 1.3 权限档位细化（per-bot 沙箱 + 执行型开关）

- **per-bot 沙箱档位**（默认开启 `botSandbox: true`）：创建/恢复 bot agent 后按能力写入 session 级 `sandbox/mode` 事件：
  - `talk` / `review` → **read-only**
  - `work` → `workspace-write`
  与已有的工具 `guard`（拒绝 write/edit/bash）形成双层防御。
  实测：bot session JSONL 中可见 `sandbox/mode` = `workspace-write`（创建默认）→ `read-only`（本插件写入）。
- **执行型 Bot 开关**：`allowWorkBots` 默认 `false`；关闭时
  - `bot.create/update` 拒绝 `capability: work`；
  - `bot_team_create_group` 在**创建群之前**预校验并拒绝（原子性，不留下空群）；
  - UI 的「能力档位」下拉不出现执行型选项。
- 验证：关闭状态下 `bot_team_create_group` 返回「执行型 Bot 未启用…（本次未创建群）」，磁盘上群数量保持不变。

### 1.4 健康检查与升级兼容

- 新增 `GET /api/bot-team.health`（登录态栅栏内）：返回 domain/schema 版本、各类记录数、关键配置、工具名、每群配额用量、冒烟状态。
- bootstrap 附带 `health` 与 `config.schemaVersion/allowWorkBots/botSandbox/配额`，UI 右栏显示 schema 版本与限流值。
- 新增文档：[升级检查清单](升级检查清单.md)（列出本插件依赖的 DSH 契约与升级后逐项验证方法）。

### 1.5 导出与 UI

- 新增「导出 HTML」：与 Markdown 导出同样的数据源，生成独立 HTML（内联样式、基础 Markdown→HTML 转换、表格/代码/引用）。
- 群头部现有「导出 MD」「导出 HTML」两个按钮；右栏显示 `schema v2 · 限 120 轮/小时`。
- 新建/编辑 Bot 的能力下拉按 `allowWorkBots` 动态收敛。
