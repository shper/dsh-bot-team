## 1. 本轮新增能力

### 1.1 模型工具（普通会话里直接操作群聊）

在插件 Host 侧全局注册 5 个工具（`host/tools.js`）；Bot 成员的 setup 会 deny 这组名字，避免自我递归。

| 工具 | 作用 | 参数要点 |
|---|---|---|
| `bot_team_list` | 列群 / 成员 / 最近消息 | `groupId?`、`includeMessages?` |
| `bot_team_create_group` | 建群并拉入/创建 Bot | `title`、`topic?`、`workspaceCwd?`、`bots[{name, provider?, model?, capability?}]` |
| `bot_team_send` | 以「助手」身份发消息并返回 Bot 回复 | `groupId`、`text`、`mentions[]`（Bot 名）、`wait`、`timeoutMs` |
| `bot_team_review` | 请某 Bot 评审一条消息，返回 verdict | `groupId`、`reviewer`、`messageSeq?`（默认最后一条 Bot 消息）、`instructions?` |
| `bot_team_discuss` | 发起多轮讨论，返回 transcript + summary | `groupId`、`topic`、`members[]?`、`rounds?`、`summarize?`、`wait?` |

工具描述遵循 agent-experience 规范：只描述行为与返回、参数规则写在参数上；返回结果有界（长文本截断并标注），并带 seq/groupId/membershipId 供后续调用。

### 1.2 查看 Bot 会话

成员卡片新增「查看会话」：通过 Client `ctx.uiWorkspace.openSession(sessionId)` 打开该 Bot 自己的 DSH 会话（真实 Agent 历史），失败时降级为错误提示。

### 1.3 群导出 Markdown

群头部「导出」：分页拉取该群完整消息（最多 50 页），生成 Markdown（群信息、成员与模型、105 条消息、评审 verdict / 讨论轮次 / 总结标记、系统消息引用块），通过 Blob 下载为 `<群名>-<日期>.md`。

### 1.4 Markdown 渲染增强

新增 **管道表格**、**删除线 `~~x~~`**（此前已有标题/列表/引用/行内代码/代码块/粗体/斜体/链接/分割线）。

### 2.3 Bot 成员工具能力 + 只读限制（验证中发现并修复 B5）

**验证过程**：让 `review` 能力 Bot 读取 `.bot-team/tool-check.txt` → 正确回复 `TOOL-CHECK-42`（只读工具可用）。

随后按该 Bot 在讨论中提出的建议，补测写权限：

| 轮次 | 结果 |
|---|---|
| 首测（修复前） | Bot 回复 `WRITE-OK`，磁盘上确实出现 `.bot-team/should-not-exist.txt`（内容 `WRITE-SHOULD-NOT-EXIST`）→ **只读策略失效** |
| 复测（修复后） | Bot 回复 `WRITE-DENIED`，明确收到拒绝理由「该 Bot 为只读能力（评审/讨论型），禁止写文件或执行命令」；磁盘**无文件产生** |

**根因**：`ctx.tools.restrict()` 只掩蔽**全局**工具；能力 preset 挂载的工具属于 agent 作用域的子树注册，restrict 对它们无效。
**修复**：在 bot setup 中为 `talk`/`review` 能力注册 `agentCtx.tools.guard()`（guard 对任何来源的工具都生效），拒绝 `write`/`edit`/`bash`/`pwsh` 等变更类工具；`work` 能力不受限。

> 这个缺陷是 M3 验证中最有价值的发现：如果只测 happy path（读文件），会把“只读型 Bot 可以写工作区”带进线上。
