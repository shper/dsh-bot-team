# Bot Team 后台会话与完整日志

Bot 在后台使用真实 DSH Agent 和持久会话，但不会在 DSH 左侧主会话列表新增条目。对话、提问和审批在 Bot Team 内完成，完整执行记录仍可查看与导出。

## 使用方式

- 在 Bot Team 单聊或群聊中继续对话。
- Bot 需要输入或审批时，在聊天里的待处理卡片中回答、允许或拒绝。离开页面后重新进入，会重新获取仍有效的交互；过期或已取消的请求不能重复提交。
- 「查看日志 / 完整日志」是独立只读入口，不激活 Agent。可查看结构化记录、完整原始 JSON，按类型与正文筛选并复制。
- 「导出 JSONL」保存原生 header 与完整持久事件，不会创建普通会话。
- 目标续跑、子代理返回等后续轮次同步到群聊，每轮单独关联回复与日志边界。

## 执行能力

新后台 Agent 显式挂载宿主默认 Agent preset，保留原生人格、工具、Skill、子代理、目标与压缩机制；Bot 身份、群上下文和模型设置在其上叠加。恢复时使用会话记录的 preset。能力取决于宿主配置和模型。

后台会话由插件通过公开 Agent create/resume 接口管理，使用宿主主列表排除的 `origin: subagent` 分类，不伪造父会话。运行时由插件根上下文创建，真实子代理仍有自己的父子归属。插件仅释放自己持有 handle 的 Agent，不销毁借用的宿主普通会话。

Bot 的 provider、model、reasoning effort 与 maxTokens 独立设置，不自动改写宿主默认模型。用户直接发送的消息保留人类来源；工具转发、讨论和自动任务带独立的 Bot Team 来源，不冒充直接人类请求。

递归 Bot Team 写入编排工具受限。当前宿主的提醒投递依赖普通 SessionController，不支持这些后台会话，因此后台 Bot 禁用创建、更新提醒；其余可用工具由 preset 提供。后台会话不提供普通原生会话的继续对话入口，提问、审批通过插件直接对接公开服务。

默认 `turnTimeoutMs: 0` 不限制执行时长。已有正数配置继续生效；若从旧版本沿用了 `300000`，改为 `0` 才会取消原来的五分钟上限。插件卸载会停止并释放它拥有的后台执行；后续使用时从持久日志恢复，未完成目标按宿主规则保持未授权续跑状态，直到用户重新要求继续。

## 新建逻辑会话与保留历史

当前工作区已完成 `/new` 的实现与本地回归。完整输入 `/new`、输入框 **+ → 指令 → 新建会话** 和顶部 **··· → 新建会话** 共用一次切换：单聊影响当前 Bot 的单聊，群聊影响本群全部成员（含停用成员），其他聊天不变。聊天身份、人格/模型设置、工作目录和项目文件保留，新建不调用模型，也不重置每日 Token 预算。

逻辑会话与底层 session 分开：全群先在同一个持久提交点采用新段，每位成员在首次执行或准备 Skill 时才分配本段的新 session；不会把旧 events、摘要或目标带入新 session。项目目录或 preset 变化仍可能在同一逻辑段内轮换底层 session。schema 7 的 conversations 与 session_bindings 记录段边界及可信日志归属；升级为旧聊天建立基线，保留既有 session 和消息，不因升级清空记忆。

旧消息留在同一时间线，以会话分隔展示。分隔与顶部 **本会话日志 / 本会话尚无日志 / 上一会话日志** 读取对应绑定；新段未使用某个 Bot 时，本段尚无该 Bot 的日志。查看历史不激活旧 Agent，已打开的执行面板固定原 session，不随新建改向。明确引用历史消息时，只把选中消息的快照带入当前请求；旧任务、评审/修改、重试和讨论不会自动恢复或派发。

从菜单新建保留正文与附件，解除旧回复目标；其他窗口切换时，非空草稿保留原归属，需点击 **将草稿用于当前会话** 后再发送。加载新 Host 后须刷新旧 Client；缺少 expectedConversationId 的外部执行请求返回 `reload-required`，旧 ID 请求返回 `stale-conversation`（均为 HTTP 409），不会静默进入新段。

## 为什么停止后仍可能无法新建

Host 在关闭新输入后检查插件执行与原生活动，释放旧 handle 后再检查一次，最后才提交新指针。已接纳的输入若只剩写盘，会先等待写入完成；写入或释放失败保留旧指针，新会话 SSE 只在持久提交后发布。回复或排队、讨论、Agent/Skill 准备、设置变更、提问/审批或正在提交回答，都可能返回繁忙原因。

原生检查使用公开服务，不为查询恢复冷 Agent：

- 查询当前、历史绑定及后代 session 的 inbox、Agent 活动、已获授权续跑的 goal 和归属该 session 的 Job。父 Agent 为 idle、界面无流式输出，都不能证明后台已结束；idle 状态下仍未完成的维护活动也会阻塞。
- Job 只有 `completed`、`failed`、`killed` 视作终态。检查本身不取消作业；停止回复或释放根 handle 不能代替对每个关联后台作业的状态检查。
- 查询受管后代并核对实时 ownership；释放插件确实拥有的根 handle 时等待公开 `drainDescendants`。`external`、`unknown` 或诊断型后代即使列表写着 inactive，也不能据此判定已结束；除非已取得对应 owned 根完整 drain 的证明，否则拒绝新建。借用、由其他所有者持有的 live 根也会阻塞，插件不会替其他所有者销毁它。
- 读取异常、无法证明安全的旧 inbox 或后代状态都返回具体阻塞信息。只有经安装版契约验证、不唤醒 Agent 的审批策略说明可作为非工作注记忽略；不会清空或丢弃未知 inbox 内容。缺少必要公开查询/收尾能力时关闭新建入口。

当前公开 SDK 没有能可靠确认 `external` 子代理终态的查询；目录中的 `catalog.activity=inactive` 只表示列表活动信息，不能证明外部执行已结束。冷重启后，已有 `external`/`unknown` 目录记录如果缺少可验证的终态证明，仍返回 unknown busy；重启不会把未知状态自动视作完成。这类情况可能持续阻塞新建，不能承诺点击停止或重启后即可 `/new`。

因此，「停止回复」之后要按返回原因等待或处理剩余工作，直到 Host 能确认结束；这里不提供「自动停止所有后台工作并立即新建」保证。

## 处理已经出现的主列表条目

插件只按成员的当前/历史会话 ID 和 Bot 回复中的执行关联识别自己的记录，不按标题或 ID 前缀猜测归属，不触碰普通用户会话。

先前版本创建的普通 Bot 会话在空闲后自动归档，从默认主列表移除；日志、消息和原 header 保留。归档不是删除，在 DSH 的归档视图中仍可找到记录。正在运行的会话、被激活的目标或宿主判定仍有工作者会延后处理，完成后再尝试；不会强制停止它们。后台会话本身不会被此流程归档。

下一次 Bot Team 派发时，普通会话会切换到新的后台会话，并保留旧会话的日志关联与群聊上下文。旧后台会话如果兼容当前 preset 和工作目录，会直接恢复；需要升级时同样保留旧历史。查看日志、导出或启动插件都不会批量激活冷会话。

## 验证与加载

在插件目录运行：

```sh
npm run check
npm test
npm pack --dry-run
```

安装版宿主验证：

```sh
ELECTRON_RUN_AS_NODE=1 "/Applications/DeepSeek Harness.app/Contents/MacOS/DeepSeek Harness" --test test/native-runtime-contract.test.js
```

测试使用临时存储与实际宿主模块，不调用模型、不启动替代服务器、不修改个人历史。普通 Node 会跳过需要安装版宿主的测试。

本轮 `/new` 的 M0 依据是 [安装版宿主契约测试](<../bot-team/test/native-runtime-contract.test.js>)：在隔离临时存储加载安装版 SDK，LLM 传输被显式禁止；验证真实 root inbox、armed goal、Job owner/终态，以及父 idle 时仍运行的受管子代理和后代 drain。无唤醒的审批策略注记也由实际审批服务产生并核实。另由 [原生活动行为测试](<../bot-team/test/conversation-native.test.js>) 覆盖未知/external 后代、冷 inbox、维护中 idle、旧会话回调与持久映射失败。

本轮安装版 Electron 契约复验 **14/14 通过**，覆盖插件拥有的后台根 Agent、真实受管 child、Job、inbox 与 goal；不调用 LLM、不操作真实聊天。该结果不消除上述 external/unknown 终态查询限制。最终 npm test 共 629 项：614 通过、15 按条件跳过、0 失败。跳过项中的 14 项为此处已另行通过的 Electron 契约，另 1 项为当前系统已有 CJK 字体时不适用的无字体反向测试。语法、差异与插件打包检查均通过；尚未发布或安装本次改动。

当前 GUI 为 [http://127.0.0.1:52573](<http://127.0.0.1:52573>)；未使用登录凭证的只读 `GET /` 与健康检查均返回 401，未进行登录后的浏览器交互或视觉验收。本轮尚未安装本次改动、重新启用插件或重启 Host，隔离契约通过不表示正在运行的 GUI 已加载新代码。

更新本地插件后重新启用插件或重启 DSH，再刷新现有 GUI。单独刷新浏览器不会重载 Host；不需要另起服务器或修改 DSH 核心。重新加载后会自动整理已存在的普通 Bot 条目，无需手动删除日志。
